# 图片对比（image-compare）

一个 macOS / Windows 桌面小工具，三个视图常驻一个窗口，左侧竖排导航或 ⌘1/⌘2/⌘3 切换：

| 视图 | 干什么 |
|---|---|
| **图片对比** `compare` | **三档布局**：1 图（单图浏览）/ 2 图并排 / 4 图 2×2，同步缩放/平移、适应窗口、100% 实际像素。布局、是否同步、滚轮行为都在工具栏「设置」抽屉里，**存盘、重启后恢复**（第九节）。走系统「打开方式」、拖文件进窗口，或**单击空窗直接把剪贴板里的图粘进来**；⌘C 复制当前图，粘进微信/Word 就是图片、粘进 Finder 是文件；载入一张带本机路径的图就会**记进「最近看过」**（左侧浏览侧栏默认就列这一份：最多 100 条、同一张只留一条、重复查看只置顶；头部可切成「当前文件夹」列它所在目录，两个源共用同一套行渲染与落窗规则，见第八节）；工具栏最右还有一枚**置顶**（`#btn-topmost`），点一下把整个窗口钉在所有应用之上，**只这一次运行有效**（#59） |
| **局域网传输** `transfer` | 自己的「文件传输助手」。可以给多台已登记的对端分别发文字、文件、文件夹，**一台还能开好几个对话框**（左边一列会话栏，一个框一行，**右键那一行就能置顶 / 重命名 / 删除聊天 / 清空聊天记录** —— 置顶的跟微信一样永远排最上、底色深一档，「清空」是两步确认且**保框删消息**）；名字、大小、进度、收发历史都画成气泡，跨日插一条年月日分隔线；**跟微信一样首屏只看最近 10 条**，滚到顶（或点顶栏）再往前翻页；拖进来或 ⌘V 粘进来的东西即发（多台混用见第五节）；**右键整条气泡（中文菜单）**：自己发的、一分钟内能「撤回这一条」（两边都只留一句提示），任意一条都能「删除（只删本机）」（对方那份不动），还能「**引用回复**」（气泡顶部一张小卡片，点它滚到原文并闪一下）与「**转发到别的会话**」（挑一个框发过去，那是一条全新的消息）；**⌘F 跨会话全局搜索**（顶栏那枚按钮同义，点一条就跳到那个框并定位到那一条）；配对设置抽屉分两页（**配对**：口令 / 设备发现 / 手动 IP / 备注名 / 解绑；**设置**：本机接收 / 存储 / 在线探测），「设置」那一页里有一节**存储**：四个占用数字 + 按 3 / 6 / 12 个月前清收件目录（聊天里引着的一个都不动）；文字/文件/图片都拦，放大层里右键也是自己那份中文菜单，不再弹 WebView 那套英文菜单 |
| **文字收藏** `fav` | 三级树（分类 / 子分类 / 条目）记笔记，可复制全文、发到当前会话、直接在对比视图里打开；焦点不在输入框时 ⌘V 粘文字会自动开一个条目接住 |

**可以同时登记多台**：每台都能主动发，而且**同一台可以反复新建对话框**（「＋ 新聊天」里再点一次那台）；
没配对过的设备发消息进来会自动建会话并计未读，不会丢东西。
没有群发、也不做中转（一条消息只落到一个对话框里）。
会话的主键是**会话自己的 ID**，不是对端 ID —— 一个对话框在两边是同一个，靠线上带 `X-Session` 保证（见第五节）。
**所有数据只存本机**，不跨设备同步、不上云（设计已确认）。

## 一、数据存在哪

数据目录由 Tauri 的 `app_data_dir` 决定，也就是应用标识 `cn.aibbl.image-compare`：

- **macOS**：`~/Library/Application Support/cn.aibbl.image-compare/`
- **Windows**：`%APPDATA%\cn.aibbl.image-compare\`（按标识推导，尚未在 Windows 实机复核）

目录下九个东西：

| 名字 | 是什么 | 写法 |
|---|---|---|
| `device.json` | 本机身份：`id` / `secret` / `name` / `passphrase`。**配对口令是明文存本地**，删掉它就等于换了台新设备 | 原子写（先写 `.xxx.tmp-*` 再 rename） |
| `peers.json` | 登记过的对端**数组**（每台：名称、备注名、IP、端口、在线状态、last_seen）+ 一份解绑名单 `ignored`。一台一条，解绑只移那一条并把它记进名单 | 原子写 |
| `sessions.json` | 会话表：**一行一个对话框**，主键是会话自己的 `id`（一台的**基础对话** = 对端设备 ID，同一台再开的框 = UUID）、所属 `peer`、显示名、读指针 `read`，加上当前焦点 `active`（也是会话 ID）与被删过的 `hidden`。上一版没有 `id` 字段，读进来由 `normalize()` 按 `id = peer` 补齐 | 原子写 |
| `messages.jsonl` | 聊天历史，**追加式** JSONL：一次状态变化就追加一行。每行的 `peer` 是**对端设备 ID**（入向取签名里的 `X-Device`，不是本机绑定的那台），`sid` 是**归属的会话 ID**（空 = 那台的基础对话，所以老历史不用改写也不会丢）。读取时同一 `id` 取**最后**一行的内容、但按**首次出现**的顺序排列（不能因为更新了状态就跳到列表末尾），所以 sending→sent 只会显示最终态；`state` 另有「queued」（对端离线、已排队等补发，见 #27）与跟着它的 `retry` / `reason` 两个字段；另有**两个可见性标记** `recalled`（撤回）与 `hidden`（只从本机删那一条，「清空聊天记录」就是批量补写它），它们与投递状态**各管各的** —— 撤回一条已送达的消息不会去改 `state`，也是靠同 ID 再追一行（`patch_flags()`），所以仍然是「只追加，不重写」（与会话表里那个同名的 `hidden` 无关，那是「删过的框」）；还可带一个 `quote`（**引用回复的小卡片**：被引那条的 id + 发送当时的摘录 / 显示名 / 类型 / 文件名快照，见第四节），新字段一律 `#[serde(default)]`，老文件与老对端没有它就等于没引用；翻页靠 `msg_history(limit, before, session)`：`session` 不传给全部历史（收藏视图用），传了就是那一个对话框的；`before` 不传给最近一页（默认 10 条），传了就是「这条之前再往前 N 条」，一页上限 500 | 只追加，不重写（「清空」也是整体重写成去重后的最新态 + 补上 `hidden`，不删行） |
| `favorites.json` | 三级收藏树，整份存成一个 JSON | 原子写 |
| `prefs.json` | 七个字段：对比视图的 `layout`（`"1"`/`"2"`/`"4"`）、`sync`（是否同步）、`wheel`（`"zoom"`/`"pan"`），加上传输视图的 `notify`（收到消息响一声，出厂**开**）、`inbox`（收件目录的绝对路径，**空串 = 用下面那个 `inbox/`**）、`inbox_layout`（根目录里怎么摆：`day` / `month` / `flat`，出厂 `day`，见第七节第 47 条）与 `heartbeat_ms`（在线探测的节拍，只认 1000 / 2000 / 5000 / 10000 四档，出厂 `1000` = 这功能可配之前写死的值）。读的时候 `normalize()` 把脏值退回默认（相对路径的 `inbox` 与白名单外的 `heartbeat_ms` 也算脏值，见第九节），**首启动没有这个文件，也不会自动写一个** | 原子写 |
| `history.json` | 侧栏「最近看过」那一份：`{ items: [{ path, seen }] }`。**只存绝对路径与最后一次看的时刻**，名字与体积都不存（存了就会过期，见第七节第 38 条）。什么算看过：新载入进图窗、侧栏里逐张翻看、传输/聊天视图里放大看过 —— 都算（第七节第 41 条）。同一张只留一条、重复查看只置顶，最多 `HISTORY_MAX = 100` 条；文件被移走 / 改名**不自动删**。读时 `normalize()` 清脏（空路径、相对路径、重复条目），**没有这个文件就是空列表，不报错** | 原子写 |
| `inbox/` | 收到的文件与文件夹，见下。这一行只是**默认位置**：`prefs.json` 里的 `inbox` 能把它挪到任何绝对路径；根目录里还会按 `inbox_layout` 再分一层日期 | 收完自动摊平 |
| `pastebox/` | 粘进界面但剪贴板里只有位图数据的东西（截图、微信里复制的图）落盘成真实文件的地方 | **只增不删** |

### 收件箱 `inbox/` 的形状（重要）

UUID 批次目录**只是传输途中的工位**：文件先落到 `inbox/<批次ID>/…`，收到最后一个文件（`X-Last`）后立刻把里面唯一的顶层条目挪到**落点目录**（出厂是 `inbox/<当天日期>/`，抽屉里能切成一个月一个或不分）：

```
inbox/
├── 2026-10-27/                ← 出厂：一天一个；切「按月」就是 2026-10/，切「不分」就直接放这一层
│   ├── 微信图片_20261027.jpg   ← 单张图、单个文件，平铺在这一层
│   ├── 简历 (1).pdf            ← 重名不覆盖，自动加 " (1)"（只在同一个落点目录里比）
│   └── 课程资料/                ← 整个文件夹保持原来的子树结构
│       └── 第一章/讲义.pdf
└── 2026-10-26/
    └── 昨天的东西.jpg
```

挪不动（权限异常等）就退回工位目录留着，绝不丢文件；多于一个顶层条目（正常不会发生）也原样留在工位目录里。

**这一处能整体挪到别的路径**（传输视图「配对设置」抽屉 →「设置」那一页 → 本机接收 → 选择…）：改的只是「新收到的东西落在哪」，
`inbox/<批次>` 那个工位也跟着长在生效目录下面（`write_stream` 本来就按 `dest.parent()` 建目录）；
里面那层日期子目录跟着搬，不用另外配。
**已经收到的文件原地不动** —— `messages.jsonl` 里每条存的是绝对路径，老气泡的预览 / 另存为 / 打开位置
继续指向老目录；`repair_inbox_paths()` 拿的是消息自己的 `path.parent()`，与生效目录无关，所以换目录不会把历史弄坏。

### 粘贴暂存 `pastebox/`

剪贴板里是**文件**时不往这里写（直接用原路径）；只有是**位图数据**（⌘⇧4 截图、微信里右键复制的图片）
才会落成一个文件，名字 `剪贴板图片-<时间戳>.png`，重名自动加 ` (1)`。
落在这里之后它就是一个普通本地文件：能预览、能发到当前会话、能另存为。

**同一份剪贴板内容反复粘只落一个文件**（按内容 sha256 认，只记最近一份）：
连着点四个空窗不会生四张一模一样的图 —— 以前会，看上去很像“粘不上/显示坏了”。

粘贴这条链路**不在运行时打日志**（排障期加的 `[clip] 剪贴板风味 / 字节数 / 落盘` 已拆掉）。
要看一次粘贴到底拿到了什么，跑只读探针（见第六节），它会把 `paste_paths` 的结果打出来；
要看剪贴板本身有什么类型，用 `osascript -l JavaScript` 列 `NSPasteboard.types`。

判“粘出来的是占位图标而不是图”的口径（手动看剪贴板时用得上）：
没有 `public.file-url`、而且位图尺寸是个整方的数（1024×1024 这类），
基本就是源只给了占位图标；粘十次会得到十张一模一样的图。

为什么不自动清：聊天气泡里的缩略图、`path` 字段指的就是这些文件，清掉就等于把历史消息里的图弄坏。
它们只来自你自己的粘贴，体积可控；真要腾空间就手动删整个目录（退出应用后再删）。

### 备份 / 迁移 / 清空

- **备份**：直接拷上面这九个东西即可，全是明文 JSON / JSONL，SQLite 之类一个都没有。`prefs.json` 不带也没关系，只是界面偏好回到出厂的两图 + 同步开 + 响一声 + 默认收件目录。`history.json` 不带也没关系，那只是侧栏那份「最近看过」（丢了就是空列表，不影响任何功能）。
  ⚠️ **`history.json` 里全是绝对路径** —— 那等于一份「你都看过哪些图」的记录（含粘贴截图落在 `pastebox/` 里的那一串）。要拷整个数据目录发给别人之前先想想清楚。
  ⚠️ **改过收件目录之后，「九个东西」就不全了**：收到的文件落在 `prefs.json` 写的那个路径里，**不在数据目录下**，按这一条打包会把它们全漏掉（`messages.jsonl` 里只剩一串路径字符，拷到新机上打开就是「文件不存在」）。备份前先看一眼 `prefs.json` 里的 `inbox` 是不是空的；不是的话，那个目录得单独拷一份。
- **换机器**：拷过去再改 `peers.json` 里那些对端的地址即可；口令一致就能继续互认。
  `sessions.json` 可以不带：首次启动会从 `peers.json` 与历史里的 `peer` 值重建会话，不带只是丢了读指针与改名。
  但多会话时代丢了它会更别扭：重建只会建出每台的**基础对话**，同一台那些另开的框只能以
  「补漏行」从历史里露出来（消息一条不少，但不挂未读、也不能改名），
  对方在那个框里再发一条才会正式建回会话行。要换机器就把这份一起拷走。
- **清空**：退出应用后删掉整个目录（下次启动会重新生成 `device.json`）。⚠️ 别在应用运行时删，会边写边丢。

## 二、每个文件是干什么的

```

├── js/                     前端：原生 ES Module + DOM，没有框架、没有构建步骤

│   ├── main.js             只做装配：导航、⌘1/⌘2/⌘3、平台文案、全局异常兜底
│   ├── api.js              invoke/listen 封装、assetSrc（本地文件 → asset:// 地址，拿不到回 null）、
│   │                       视图状态、拖拽与粘贴的路由（drop + 悬停 + ⌘V）、toast
│   ├── view-compare.js     对比视图：图窗、同步缩放平移、键盘（含 ⌘C 复制图片）、原生拖拽落点判定、
│   │                       浏览侧栏（两个源可切：默认「最近看过」/「当前文件夹」；小图首选 asset 地址，取不到文件或转不出地址就退回
│   │                       整图 base64，屏上看得见几行就挂几行）
│   │                       与按可见窗序列轮转落窗、

│   │                       三档布局（1/2/4 图，`LAYOUT_KEYS` 是「哪些窗可见」的唯一口径）、
│   │                       工具栏控件与「设置」抽屉的双向联动 + prefs 读写、

│   └── style.css           全部样式（含 [hidden] 统一规则、CSS 变量主题）
├── src-tauri/              Rust 侧：网络、存储、安全全在这里，前端只发意图

│   │                       （只列本层图片、封顶 2000）、copy_text、set_always_on_top（把主窗钉在最前面，
│   │                       只改窗不写盘）、单实例交接、命令注册表
│   ├── src/store.rs        device/peers/sessions/messages/favorites/prefs/history 读写、sha256 签名与 ±300s 时间窗、
│   │                       safe_rel_join 路径守卫、头值 base64 编解码、原子写；历史去重只有一份实现
```

## 三、跑起来 / 打包

```bash
npm install                      # 只装 @tauri-apps/cli

npm run dev                      # 开发：vite + rust 热重载
RUSTUP_TOOLCHAIN=stable-aarch64-apple-darwin npx tauri build --bundles app
```

> **Apple Silicon 必须显式指定 `stable-aarch64-apple-darwin`**，否则可能编出 x86 包、在 M 机上靠 Rosetta 跑或直接白屏。

发版要改**两处版本号**：`src-tauri/tauri.conf.json` 与 `src-tauri/Cargo.toml`（`Cargo.lock` 由 cargo 自动更新）。`package.json` 里的 `version` 只是 npm 元数据，不参与打包，当前仍是 `0.1.0`。

发布流程：

```bash
git tag -a v0.2.1 -m "说明"
git push origin main && git push origin v0.2.1   # tag 触发 CI 出双平台包并建 Release
```

CI 里 `RELEASE_TAG` 非空才创建 Release；只推分支不带 tag 时产物只进 Artifacts。GitHub Actions 之外本机没有别的发版通道（本仓库走 SSH，HTTPS 不可用）。

文件夹整批大小与子树搬迁；倒数第二段「两个身份打同一台接收端」：落库的 `peer` 必须是签名里那个
`X-Device`（不是本机绑定的那台），两个身份各占一行会话、同一身份不会多出第二个框；
最后一段「同一台靠 `X-Session` 分落好几个框」：不带 `X-Session` 落基础对话（上一版兼容）、
本机没见过的会话 ID 被认下来、`/msg` 与 `/file` 同一个 `X-Session` 落同一个框、
同一台三个框各存各的、新框名字取 `X-Session-Name` 且对端后来改名不会覆盖本机、
以及拿别人的会话 ID 塞消息会落回自己这台的基础对话。
脚本自己登记并清理写进收件箱的测试文件，`messages.jsonl` 不动（条目都带「自检」字样），
但这两段会在会话列表里留下几行（本机身份、「自检乙机」与两个话题框），跑完在界面上删掉即可。

⚠️ **跑之前确认没有任何实例还在跑**：应用启用了单实例插件，第二个进程只会把参数交给已运行的实例然后立刻退出
（还会把对方窗口顶到前台），你的请求实际会打到那台正在运行的实例上，表现为口令不匹配的一堆 FAIL。
**绝不要**为了「干净环境」去删应用数据目录 —— 那里是真实聊天记录与收件箱，删了不可恢复。

不想把自检的假消息写进真实历史，就把整个运行环境挪到 /tmp（数据目录由 `app_data_dir` 推导，跟着 HOME 走）：

```bash
D="Library/Application Support/cn.aibbl.image-compare"
SB=/tmp/xfer-sandbox-home
mkdir -p "$SB/$D"
cp "$HOME/$D/device.json" "$SB/$D/"          # 只借口令与设备身份，历史与会话都不带走
HOME="$SB" ./src-tauri/target/debug/image-compare &   # 窗口会弹一下，数据全落 /tmp
HOME="$SB" node tools/net_selftest.mjs                # 两边都要带上同一个 HOME
kill %1; rm -rf "$SB"
```

沙盒里没 peers.json 也没 messages.jsonl，首次启动的迁移什么都不会建（新装就是这个空状态）；
自检产生的历史与会话都在 /tmp 里，跑完整个目录删掉就干净了。

## 四、局域网这一套的约定

页面 origin 是 `ipc://localhost`，在 webview 里直接 `fetch` 局域网地址会被混合内容策略与 CSP 双重拦掉，
所以**网络全部实现在 Rust 侧**，前端只 `invoke` + `listen`，不新增任何 capability 权限。

- **端口**：默认 `45789`，被占用时依次 +1，最多试 10 个。每台机器各自监听，实际端口在连接面板上显示。
- **发现**：mDNS 广播并浏览 `_imagecmp._tcp.local.`。公司网络 / VPN 常屏蔽 mDNS，看不到设备就用「手动 IP」绑定。
  注意 macOS 上主机名必须以 `.local.` 结尾（带尾点），否则 mdns-sd 注册会失败。
- **解绑不等于拉黑入向**：解绑那台会记进 `peers.json` 的 `ignored`，心跳从此不再把它自动登记回来（它仍留在
  「已发现」候选里，点一下才算亲手重新添加；手动 IP、重新探测同样算）；但它发过来的消息照收、
  照归到原来那个对话框。为什么必须有这份名单见 #25。
- **对端备注名只存本机**（见 #26），**离线排队也只存本机**：已配对 + 离线时点发送不报错，
  那一条以 `state:"queued"` 落进 `messages.jsonl`，对端**整件事毫无感知** —— 没有「排队」这种协议头，
  也没有「催一下」的额外请求。它上线后由本机心跳把队列投出去，文字走的是当初写下的那个 `ts`，
  所以对面看到的是「你当初写它那一刻」、日期分隔线也按那天插（与微信一致）。未配对的仍然当场拒，
  因为连 `host:port` 都没记下、排队也无从排起。为什么不能只挂「离线转在线」那个边沿见 #27。
- **一台设备在界面上只有一个名字**：`Peer::display_name()` = 备注名 > 对方上报的设备名 > 露一截设备 ID。
  备注名只存本机、不参与签名、也不发给对端（对端那份名字归它自己维护），见 #26。
- **鉴权**：请求头 `X-Device` / `X-Ts` / `X-Sig`，签名 = `sha256(口令|设备ID|时间戳|body摘要)`，时间窗 ±300 秒。
  **未设口令时一律 403**，避免误把开放端口当传文件通道。服务端**不校验发送方是不是本机绑定的那台**：
  `X-Device` 伪造过不了签名，所以入向消息的 `peer` 直接取它 —— 这条是「谁发来的就归到谁的会话」的地基。
  同一台的几个框靠头上的 `X-Session` 分（它不进签名，只分落点与起名）。
- **文件头**：`X-Size` / `X-Sha256` / `X-Name` / `X-Rel-Path` / `X-Batch` / `X-Last` / `X-Batch-Size` / `X-Device-Name` / `X-Session` / `X-Session-Name`。
  头值只能 ASCII，所以中文名、相对路径、设备显示名与会话名统一 base64；发送前显式拒绝非 ASCII 或含换行的头。
  `X-Session` 是会话 ID（UUID 或设备 ID，本来就只有 ASCII），所以直接明文。
  `X-Device-Name` 与 `X-Session-Name` 都不参与签名，只用来给第一次出现的陌生会话起名（改名不该让旧请求失效）；
  老版本根本不发这两个头，名字退回设备 ID 的一截。
- **校验**：边流式写盘边算 sha256，与 `X-Sha256` 不符就删掉临时文件回 422，不留半成品。
- **路径守卫**：`X-Rel-Path` 只允许 `Component::Normal`，`..` / 绝对路径 / 符号链接组件一律 400。
- **大小上限**：`/msg` 1MB，单文件 8GB。聊天里的图片预览另有口径：≤4MB 自动出图，>40MB 不解图，
  引导用「在对比中打开」。
- **Windows 第一次监听会弹防火墙授权**，不点允许就对端永远发现不了本机（走手动 IP 也一样连不上）。

### 未读角标：图标上、按钮上、会话行里，是同一个数

三处显示、一个口径：数字全部来自 `Hub::sessions_json()` 每行 `unread` 的求和，不另算第二套。
「未标记」与补漏行在后端已被置 0，所以它们掺不进角标（超 99 显 `99+`）。

| 位置 | 实现在哪 | 为什么写在那 |
|---|---|---|
| 会话栏每行 | `sessionNode()` | 本来就有，是口径的源头 |
| 左侧「传输」按钮 | `renderNavBadge()`，由 `renderSessionRail()` 调 | 只挂 `applySessions` 会漏：本地累加未读那条路（`bumpRail`）不走 `applySessions`，结果是会话行涨了一个、按钮上的数不动 |
| 应用图标 | `src-tauri/src/net/badge.rs`，由 `Hub::emit_sessions()` 推 | 不能交给前端算：macOS 上关掉最后一个窗进程也不退（tao 没实现 `applicationShouldTerminateAfterLastWindowClosed`），没人算就等于冻在旧数字上 |

- **唯一出口**：`emit_sessions()` 一次 `sessions_json()` → `emit("sessions-changed", payload)` → `badge_total(&payload)` → 主线程 `apply_badge`。三件事共用这一份 payload 是刻意的，分成两次算就会在两个线程读到两个版本的历史。裸的 `emit("sessions-changed", ...)` 一处都不许留（留下的那一处不会刷角标），这条已钉进 `prefs_layout_check` 的静态合约。
- **封顶两边一个数**：Rust 的 `BADGE_CAP = 99` 与 JS 的 `total > 99 ? "99+"`。mac 走 `set_badge_label` 而不是 `set_badge_count` —— 后者内部就是 `count.to_string()`，显不出 `99+`。
- **归零时机**：仍只在读指针推进（`session_focus`）时自然归零，**不做**「窗口拿到焦点就清」。额外一处：macOS 上关窗（`RunEvent::WindowEvent` + `CloseRequested`）主动清一次 —— 窗销毁后 `get_webview_window` 就拿不到窗了，不清就会留个点不开的红数字。
- **冷启动也有初值**：`setup` 里 `app.manage(hub)` 之前先 `hub.emit_sessions()` 一次，历史里已有的未读在启动那一刻就上图标。
- **做不到的一族**：Windows 任务栏只能贴一张覆盖图标（`net/badge.rs` 里 `overlay_dot()` 现算的 32×32 裸 RGBA 红点，不引 image crate），**显不了数字**，所以「有没有未读」在两个平台上长成两种样子；这是平台能力不是 bug。托盘、系统通知弹窗、@提及本期未做。
- 角标长在自己看不到的地方（窗关了更看不到），所以 `apply_badge` 留了一句 `[badge] 未读 N → 角标 X` 日志：出问题时分得清是「没算」还是「算了没显」。

### 配对设置抽屉的两页：配对是配对，设置是设置

入口还是顶栏那枚「配对设置」（`#btn-xfer-settings` → `#xfer-settings`），但抽屉里分了两页（`#xfer-tab-pair` / `#xfer-tab-prefs`，各带一个 `#xfer-page-*` 容器）：

| 页 | 装什么 | 走哪条命令 |
|---|---|---|
| **配对** | 本机设备名与配对口令、候选设备、手动 IP、对端备注名、「重新探测在线」与「解绑当前对端」 | `set_pair_config` / `set_peer_alias` / `bind_peer_addr` / `reprobe_peer` / `unbind_peer`，全是对端身份那一路 |
| **设置** | 本机接收（提示音 / 收件目录 / 怎么摆）、存储（四个数字 + 清理）、在线探测（心跳节拍） | 全在**同一份** `prefs.json`，一个 `get_prefs` / `set_prefs` 对 |

- **抽屉标题跟着当前页走**（`#xfer-settings-title` 写「配对」或「设置」）：两页顶着一个「配对设置」，会让人在设置那一页里找口令。
- **切页只翻 `hidden`，不重建 DOM**：重建会把刚填一半的口令与「清理 / 删除」那两步确认的臂一起弄没。假 DOM 不解析 HTML，这一条只能拿静态合约钉（谁在哪一页、默认露哪页、页签类名 CSS 两边都在）。
- **默认落在「配对」那一页，收起再打开回到人刚待过的那一页**：当前页只存在模块变量里，不写 `prefs.json` —— 「上次看哪页」不值得占一次磁盘写，也不该跨重启。
- **只在这一页真露出来时才读磁盘**（`get_prefs` + `inbox_dir` + `storage_stats`）：以前抽屉一打开就递归走一遍目录树，而十有八九用户是来改口令或看候选的。同一次打开里来回切页不重读，要重看靠那颗「刷新」。

### 本机接收：收消息响一声，与收件目录放哪

这些都住在上面那个抽屉的**「设置」那一页**（`#xfer-page-prefs` → 本机接收 / 在线探测），存在**同一份** `prefs.json`，与对比视图那三项共写一个文件（靠的还是「只传改动那一项」的局部更新语义，两个抽屉不会互相冲掉）。

| 项 | 存在哪 | 生效点 |
|---|---|---|
| 收到消息时响一声 | `notify`（出厂**开**） | `Hub::notify_arrived()`：落库后调，先读开关、再按 `msg_id` 去重，然后 `net/sound.rs::play()` |
| 收件目录 | `inbox`（空串 = `<数据目录>/inbox`） | `Store::inbox_dir()`：工位与摊平目标都问它，启动建目录也问它 |
| 收件目录里怎么摆 | `inbox_layout`（`day` / `month` / `flat`，出厂 **`day`**） | `Store::inbox_delivery_dir()`：摊平目标另算一层日期子目录，见 #47 |
| 探测对端在线的间隔（同一页的「在线探测」那一节） | `heartbeat_ms`（四档 1000 / 2000 / 5000 / 10000，出厂 **1000**） | `net/client.rs::spawn_heartbeat()`：**每一拍重读一次**，改完不用重启；离线判定是连续 3 拍，补发也挂在这一拍上（见 #27），所以这一档同时决定「判离线要几秒」与「上线后最多等几秒开始补发」 |

- **发声在 Rust，不交给前端**：WebKit 默认要求用户手势才能播媒体，而后端 push 进来那一刻没人在键盘鼠标上；加上 macOS 关掉窗进程也不退、前端根本不在场 —— 与上面角标那一段是同一个道理，展开见 #34。
- **响是无条件的**：正看着这个会话也响。唯一去重是同一条 `msg_id` 只响一次（发送端 retry / 离线补发会把同一条再投一遍）。
- **一个文件夹 = 一声**：`/file` 本来就是整批收完（`X-Last`）才落**一条**消息，粒度天生如此，没再加时间节流。
- **不引新依赖**：mac 用 `Command::new("afplay")` 起子进程（`spawn` 不等待，不拖住落库那一步），与 `reveal_in_folder` 里的 `open -R` / `explorer /select,` 是同一套打法；Windows 用 `MessageBeep(MB_ICONASTERISK)`，**跟随系统的提示音设置**（比绑一个 wav 更不容易「怎么没声」），只给已有的 `windows` 依赖加一个 feature `Win32_UI_WindowsAndMessaging`。mac 的音效按候选顺序取第一个存在的（精简过的系统可能缺 `Tink.aiff`）。
- **「试听」无视开关**（`play_notify_sound`）：这一声就是用来确认「这台机器到底放不放得出声」的，跟着开关走就分不清是「关了」还是「坏了」。
- **改目录只影响新收到的**：`set_prefs` 里那一条是硬闸门（必须绝对路径 + `create_dir_all` + 是目录），验不过直接报错且**不动磁盘上那份旧值**；老文件留在原处，见第一节。
- **摆放规则也只影响新收到的**：`day` 落 `inbox/2026-10-27/`、`month` 落 `inbox/2026-10/`、`flat` 直接落 `inbox/`；日期取**收完那一刻的本地时间**（不是 UTC，也不是开传那一刻），整个文件夹发过来就是那个日期目录下的一个同名子文件夹。存好的不会被搬动、不会被重命名 —— 聊天记录里的 `path` 是绝对路径，搬了就等于让旧气泡一起失效。
- 那两项**只在「设置」那一页露出那一刻读**（`get_prefs` + `inbox_dir`），不进启动路径，也不在「配对」那一页时顺手读；失败一律把 Rust 那句带路径的原因原样上屏。
- 日志：响了就打 `[sound] 叮 <id>`（听见了还得能在日志里对上号）；放不出声也只打日志，不会因为它把落库链路带崩。

### 待发送区：先摆着，点发送才发

选文件 / 选文件夹 / 拖进窗口都只往 `#xfer-attach` 里放，一个字节都不会出去；点「发送」或 Enter 时
`sendComposer()` 才依次调 `send_paths`（这批路径）与 `send_text`（输入框里的字）。离线语义没变：
这时 `send_paths` 照样把东西落成 `state:"queued"`，照样等对端上线补发，只是多了「点一下才走」这一步。

- **`stat_paths` 是纯读**：`std::fs::metadata` 拿名字 / 大小 / 是不是目录，不开文件、不算哈希、不发网络。
  路径已经不在了也留在列里（`missing: true`），界面标红并在发送前拦住 —— 拖进来之后被移走是常事。
- **待发送区不认会话**：它只是“下一句要发的东西”，切到哪个框就发给哪个（标题跟着变成「点发送就发给「这个」」）。
  以前用过 `attachSid` 记归属并在切走后拦下，结果粘一张图、切个框就卡在「属于「某某」，当前不在这个会话」的黄字上，
  既发不出去也不好猜该删哪一个（用户报过）；**对比视图右键「发送到聊天」投进来的那批也一样**，
  进去就摆好、选谁发给谁，按发送那一刻才真的出去。
- **上限 50 个**：横向一排放不下更多，也顺手挡住整目录误拖。
- **只有发成功的那部分才从输入区移除**：文字与附件是两次 `invoke`，任一次抛错都只清已经成功的那个。
- 缩略图仍走 `assetSrc()`；`img` 的 `error` 一响就换成扩展名方块（与侧栏小图同一套退路）。

### 撤回与本机删除

右键整条气泡（文字 / 文件 / 图片都拦），弹的是自己的中文菜单（`#chat-msg-menu`，与对比视图那套 `.ctx-menu` 共用样式与 `placeMenuAt`）：

| 哪一条 | 露什么 | 后果 |
|---|---|---|
| 本机发出的、没撤过、还在一分钟内 | **撤回** + 删除 | 两边都只留一句提示（本机「你撤回了一条消息」、对方「对方撤回了一条消息」），正文/预览/缩略图全拆掉；会话栏摘要变成「撤回了一条消息」，那条不再计未读 |
| 本机发出的、过了一分钟 | 只有删除 | —— |
| 对方发来的 | 只有删除 | 删除只让**这一台**不再显示它，对端那份与收件箱里的文件一概不动，也不限时间（这是它与「撤回」的唯一区别） |

- **「一分钟」的判据只有一份**（`store::RECALL_WINDOW_MS` + `recall_check()`）：前端那个 `RECALL_MS` 只决定入口露不露，真拦在后端 —— 一个框开了几分钟没重画，入口还挂在屏上，点下去就该被拒。
- **文件与图片也能撤回，但只改显示**：已经落进收件箱的那个文件不跟着删（它可能早被人打开过、也可能已被移走）。
- **排队还没送出去的那一条**：撤回就是直接出队（`pending_messages()` 同时避开 `recalled` / `hidden`），对方上线不会再补发 —— 那等于把用户撤掉的东西又送回去。
- **已送达的必须先让对端撤成功，本机才跟着改**：反过来的话本机那句「已撤回」是假的（对方还挂着原文）。被拒就当场收起入口 + 一句原因，只弹 toast 用户还会反复点。
- **新协议 `POST /recall`**：body 只有 `{"msg_id"}`，走同一套口令签名 + `X-Device`；对端拿签名里的设备 ID 比这条的 `peer`，**只有发送者本人能撤自己那条**。找不到那条 / 本机已把它删了 → 回 200（幂等：目的就是让对方不再显示它，而这里已经不显示了；回失败反倒让发起方以为撤不掉）。请求**故意不带 `X-Session`**：带了会让对端顺手把「对方那个框」在本机建出来，撤回不该有这种副作用。老版本根本没这个路由，404 翻成人话「对端版本不支持撤回（它还没更新）」。
- **一处真竞态**：投递与补发落库拿的都是**开始前的快照 clone**，这期间用户刚把这条撤了，一次成功的投递就会把「已撤回」冲回 false，撤走的东西会在两边同时复活。所以每处状态写入都先过 `with_flags()` 把盘上最新的两个标记盖回来；`mark_sent()` 成功后如果这条已经 recalled，再补投一次 `/recall`（这次往返的失败不能把那条投递判成失败）。
- **删除要两下**（与会话行那枚同一套手感：先变成「确认删除？」，4 秒内再点一次才真删）—— 手快点掉一条虽然对方那份还在，自己这边可补不回来。删掉的正好是当前页最早那条时，得把翻页游标 `oldestId` 挑到还留着的那条上（后端把失效游标当成「从头给最新一页」，不改就会「加载更早」原地打转）；整页删空但更早还有历史时得让后端再给一页。

### 放大层里右键（第三份中文菜单）

对比视图的图窗 / 侧栏行、传输视图的聊天气泡都换成中文菜单之后，**放大层是唯一还会弹系统英文菜单的地方**，现在也补了一份（`#lightbox-menu` 五项：复制图片 / 另存为… / 复制文件路径 / 在文件夹中显示 / 在对比中打开）。

- **没本机路径就不拦**：`lightboxPath` 为空（剪贴板粘进来的纯位图，没落盘）时直接交给系统 —— 那里唯一有用的「拷贝图像」比一排灰色的文件项有用。
- **五项全走已有命令**（`api.js` 里的 `copyPathAsFile` / `save_path_as` / `copyText` / `reveal_in_folder` / `openInCompare`），`js/` 里没新增一个后端口子。另存为在选文件框里按取消返回 `null`，那不是失败，不弹提示。
- **没有按类型显隐**：放大层里本来就是图，五项在有路径时全露（与气泡菜单那套动态显隐不同，所以**没抽到 `api.js` 里共用**：两个视图的菜单 DOM 与显隐需求本来就各有一份，抽公共反而绕）。
- 与旧监听不冲突：Esc / 点背景关层那套照旧，菜单打开时 pointerdown 先收菜单；**收菜单的那一下 click 会落到背景上，拿 `lbKeepLayerOnce` 只吃一次**，否则右键弹出自家菜单再点一下选中项会把整层连带关掉。
- 在对比中打开那一项先 `closeLightbox()` 再 `openInCompare([p])`：带着这一层切去对比视图会把 overlay 盖在另一个视图上。

### 引用回复

右键气泡多一枚「**引用回复**」（没被撤回、而且算得出一句摘录才露：文字引正文、文件与图片引那一个文件名）。点下去输入框上方出现一条预览横条（左边一根蓝色竖线 + 「引用 某人：摘录」+ 右边 × 取消），Enter / 点发送时跟着正文一起走，发出即清。

- **引用不要求本机路径**（与「另存为 / 在文件夹中显示」那一组不同）：正在收、路径还没到手的那一条也能引 —— 引的只是屏幕上看得见的一句话。
- **`quote` 是发送那一刻的快照**（被引那条的 `id` + 摘录 + 显示名 + 类型 + 文件名），不是引用一个指针：原文后来被撤回、被删、被人改了名，气泡上那张卡片还是当时那句话（名字也是当场算好存死的，不回头改旧卡片）。
- **摘录 120 字符截断**（`QUOTE_MAX`，与后端 `Quote.text` 的注释同一口径），而且**按字符切不按字节** —— 一个中文一个字在 `.length` 里占两个，按字节切会拦腰掉字。
- **气泡顶部一张 `.quote-card`**：点它滚到被引那条并闪一下（`flashNode`，与全局搜索共用这一套）；**不在已铺出来的页面里就只说一句「原文还没加载出来」**，不为点一下卡片把几十页历史全拉出来（逐页找那是全局搜索那边的活）。
- **不需要协议版本号闸门**：`send_text(text, to, quote)` 只是把它原样塞进 wire JSON，`Message.quote` 是 `Option<Quote>` + `#[serde(default)]` + `skip_serializing_if`，所以**老对端与老 JSONL 没有它就等于没引用**（降级成一句普通文字，不报错），旧行读得开、带未知字段的行也读得开。没引用时不往盘上写这个键，所以历史文件不会因为这条功能而涨胖。

### 转发到别的会话

菜单里「**转发到别的会话**」（没被撤回，且有正文或有本机路径才露）→ 弹一个会话选择浮层（`#xfer-fwd-pick`，与「＋ 新聊天」同一套 `.pick-list` 组件），列的是**除了这一条所在那个框以外**的所有会话，一行就报「会话名 · 最后一条时间」。

- **零新后端命令**：文字走现有 `send_text`（不带 quote），文件/文件夹走现有 `send_paths`（路径就是本机那一份）；离线对端照旧自动入队，不用先切会话再发。
- 转出来的是**全新 id 的新消息**，两边各会话的撤回 / 删除 / 清空互不影响（这条口径也写进功能表了）。
- 正在收、还没落盘的那一条（占位气泡没有 `path`）**菜单项不露** —— 手里没东西可发。
- 只一个会话也没有（或只有当前这一个）时，浮层里那一行禁用文案说「还没有别的会话：先从顶上「＋ 新聊天」开一个」，不静悄悄。

### 清空一个对话框的历史

会话行右键多一枚「**清空聊天记录**」，与「删除聊天」同款两步确认（第一下只把文案换成「再点一次清空」，4 秒没人点自己退回）。

| | 会话行 | 对端 | 对方那份 | 收件目录里的文件 | 本机这框的消息 |
|---|---|---|---|---|---|
| 删除聊天 | 没了 | 还在 | 不动 | 不动 | 不动（只是不再列出这个框） |
| 清空聊天记录 | **还在** | **还在** | **不动** | **不动** | 全部补写 `hidden` |

- **后端 `session_clear(id)` → `Store::clear_session()`：一次全量读 + 一次整体重写**（走 `raw` 那一条读取路径，不经 hidden 过滤），把属于 `sid` 且还没 hidden 的那些逐条补上 `hidden`，写成去重后的最新态。不能一条消息一次 append：几百条历史就是几百行 IO 放大，而且重写一遍本来就不删行。
- **与单条「删除（只删本机）」共用同一个标记**，所以 `read_messages()` 这一挡下去，分页、会话栏摘要、未读、角标、全局搜索天然一起跟上；已经撤回过的那条也会被标上（它本来就看不见了）。
- 重复清一个已经清空的框回 0 条且**行数一行不多**（已 hidden 的不重复补写）。
- 「未标记」那一行也支持（它的 sid 就是那个空串筐）。
- 清完当前那格重铺一次：空态文案说准一点——「聊天记录已清空：对方那份与收到的文件都还在」，而不是「还没有消息」（消息还在盘上，只是这一台不再显示）。

### 跨会话全局搜索（⌘F）

传输视图里 ⌘F / Ctrl+F（或顶栏那枚「搜全部会话」）弹一个浮层：一个输入框 + 一组类型 chips（全部 / 文字 / 图片 / 文件 / 文件夹）+ 结果列表，Esc 或点外面收。

- 与会话内那条小搜索框**并存、语义一字没改**：那一边只筛已铺出来的气泡，这一边查整份历史；它的 placeholder 里多了一句「⌘F 搜全部会话」。
- **后端 `search_messages(query, kind)`**：读 `read_messages(usize::MAX)`（这一出口已挡 hidden，所以撤回与删过的天然不露），匹配面是「正文 + 文件名 + 引用摘录」三行拼起来的一整个串（所以引用里那句话也能搜到），大小写不敏感；每条命中回 `{ id, sid, peer, ts, kind, name, dir, session, snippet }`，摘录取命中处前后各 24 字符（`SEARCH_WINDOW`），按 ts 降序封顶 200 条（`SEARCH_LIMIT`，列满时补一句「先列最近这 200 条：关键词再具体一点」）。
- **命令层与算结果层分开**：`search_messages` 只负责取历史与两张名字表（会话名的口径与会话栏完全同源：会话名 > 对端备注名 > 露一截设备 ID > 「未标记」），`search_rows()` 是纯函数 —— 大小写、空词闸门、匹配档、匹配面、摘录、排序封顶**只有这一份**（命令层再特判一次就是两个地方会改一个漏一个，已钉进静态合约）。拆开也才能凭空构造一份历史跑单测 —— 命令本体要 tauri 的 `State` 才调得动。
- **点一条就到位**：`openSession(sid)` → 目标没铺出来就逐页 `loadOlder` 直到出现（封顶 60 页，与会话内「拉齐」同口径）→ 滚到中间闪一下；翻完还没见到那句说人话（「原文还没加载出来」）。
- 逐字符全量重读一份 JSONL 不便宜，所以输入有 250ms 防抖，而且**重画前用户又改了词就丢掉这份过时的**；Enter 不等防抖。

## 五、多台（≥3）怎么用

一句话结论：**三台同时往一台推可以；一台同时给多台推也可以，而且每台还能开好几个对话框；三台两两随时互发仍然做不到。**

为什么能“同时收”：`/ping` `/msg` `/file` 只校验口令签名，**不校验发送方是不是本机登记过的哪一台**
（`X-Device` 只是签名的输入之一）；接收端每个请求一个线程，批次状态按 `batch id` 隔离在
`Hub.batches`，所以多台并发推互不串，传大文件时别人的请求也进得来。口令对得上的来者就能发进来，
本机这边由 `ensure_session` 自动建会话并计未读 —— 没配对过也不丢消息。

为什么能“主动发多台”：`peers.json` 存的是数组，会话栏里每个框一行，发文字与发文件都发给**当前对话框**
那一台（`send_text(text, to)` / `send_paths(paths, to)`，`to` 是**会话 ID**，不传就取当前那个框；
发送时由它反查所属那台的地址）。没有群发：一条消息只落到一个对话框里，也不做中转。

### 拓扑得想清楚（三台两两随时互发做不到）

| 想要的效果 | 怎么连 | 结果 |
|---|---|---|
| 往主力机汇拢（最常见） | Mac 登记 B；C 登记 Mac | B↔Mac 双向可发；C 推给 Mac 不用登记也能发进来（自动建会话），Mac 要主动发给 C 得先把 C 登记上 |
| A、B、C 都要能主动互发 | 每台都把其它两台登记上（各自点一下候选或手动 IP） | 可以，但每台都得直接可达；没有中转 |
| 只在 A 上配一次对，B↔C 就自动通 | **做不到** | 心跳只 ping 本机自己登记过的那些对端，从不替别人转发 |

### 同一台开好几个对话框（多会话）

会话的主键是**会话自己的 ID**，不是对端 ID：

- 一台的**基础对话**直接拿对端设备 ID 当会话 ID。上一版根本没有 `sid`，老历史因此能不改写就归位（`Message::sid_of()`：`sid` 为空就按 `peer` 算）
- 同一台再开的框用另造的 UUID，由发起方生成
- 一个框在两边是同一个：发出去的每条请求都带 `X-Session`，对端按它分落点；在线态、地址、端口则统一取自**所属那台**（`Session.peer`），一台的几个框共用

入口只有一个：「＋ 新聊天」弹层里再点一次那台（名字上会写「已有 N 个，再开一个」）。
会话栏那一行只放「改名」与「删除」两个按钮 —— 栏子只有 214px，按钮再多名字就被挤没了；置顶在右键菜单里
（右键会话行，跟微信一样：置顶的永远在最上面、底色深一档，见第七节第 49 条），解绑也不在行上，
去「配对设置」里的「解绑当前对端」。要注意弹层只列已登记与刚发现的设备：那种只发过消息、还没登记的
对端（会话栏里有它一行但弹层里找不到），得先在「配对设置」里手填 IP 登记，才能在它身上再开框。
新框自动叫「设备名 · 月-日」（**本机的本地日期**，所以日期由前端算完传 `session_new(peer, name)`，Rust 侧只有 epoch 毫秒、算不出时区）。
同一天在同一台再开一个必然撞名，后端 `unique_name` 会加 `(2)`、`(3)` 区分（只在同一台范围内比）；
拿不到设备名（还没登记过的那台）就退回「设备名 · 话题 N」编号。想叫别的就点那一行的「改名」当场改。
**名字是建的时候定下、之后两边各改各的**：对方那个框改了名，不会把本机这行顶掉；反之也一样。

收到的消息归哪个框由 `resolve_incoming` 定，四条落点规则：

1. 没带 `X-Session`（上一版）、或带的就是发送方自己的设备 ID → 那台的基础对话
2. 本机已有这个会话 ID、且它确实属于这台 → 就用它（两边同一个框）
3. 本机已有这个会话 ID、但它属于**另一台** → 退回发送方的基础对话（不能拿别人的会话 ID 往别人框里塞消息）
4. 本机没有这个会话 ID → 认下来（对方先在自己那边开了个框，这边跟着建一个）

还有一种不进这四条的：`X-Device` 为空（认不出谁发的）既不新建也不归属，那几条只进「未标记」那一行看。

落点只看 `X-Session` 这个 ID，**不当名字当真**（名字是 base64、不签名、可以随便报）。
未读、分页游标、日期分隔线全部按会话 ID 各算各的，所以一个框翻到一半不影响另一个框。

### 首次准备清单

1. 每台填**完全相同**的配对口令（≥ 4 字符），设备名改成一眼认得出的（上限 40 字符）—— 设备名就是
   会话栏里那台**基础对话**那一行的名字（对端通过 `X-Device-Name` 报过来），同一台再开的框在后面添「· 月-日」。
2. **Windows 第一次监听会弹防火墙授权，必须点「允许」**。不点对端永远发现不了本机，走手动 IP 也一样连不上。
3. 每台的实际监听端口看连接面板。默认 45789，被占自动 +1，**三台端口很可能不一样**，手动 IP 时要填对。
4. 每台系统时间对齐。签名有 ±300 秒时间窗，超窗报的是「配对口令不匹配或时间戳超窗」，极易误判成口令写错。
5. 登记入口：会话栏点「＋ 新聊天」把候选与已登记的设备列在一起，点一台未登记的就是「配对 + 建基础对话 + 切过去」，
   点已经登记过的那台就是**在它名下再开一个对话框**；
   「配对设置」里点已发现的那行也可以；mDNS 被公司网络/VPN 屏蔽时直接走手动 IP。

### 两条纪律

- **别同名同时推。** 重名判定是「先看存在、再改名挪过去」，两台同一瞬间都推 `讲义.pdf`，
  其中一个挪不动会退回工位目录 `inbox/<UUID>/…`（文件不丢，但位置难看）。文件名带上设备前缀最保险。
- **删会话要先确认一次，而且不删历史。** 那一行的「删除」得连点两下：第一下只把按钮变成
  「确认删除？」（4 秒内不点第二下就复位）—— webview 里 `window.confirm` 不可靠，所以确认就地长在按钮上，
  与收藏视图的删除同一个口径。第二下只删**这一个对话框**与它的读指针：这个框会从列表里消失（会话 ID 记在
  `sessions.json` 的 `hidden` 里，不会被历史又补回来），同一台的其它框完全不受影响；
  以前发来的东西一条不少，对方在那个框里再发一条就自己回到列表。
  要真清掉历史，只能退出应用后手工删 `messages.jsonl`（不可恢复）。

### 连不上时的排查顺序

1. 状态条写「接收服务未启动」→ 端口 45789~45798 全被占，或防火墙没放行（原因原文会带在状态条里）。
2. 「已发现设备：无」→ mDNS 被屏蔽（公司网络/VLAN/VPN 的常态），直接走手动 IP，别等。
3. 「对端离线」→ 那台 app 没开，或 DHCP 换了 IP。点「配对设置」里的「重新探测在线」，不行就重填 IP。
4. 「配对口令不匹配」→ 先怀疑系统时间（±300 秒窗），再怀疑某台改了口令忘改其它几台。
5. 「还没添加这台，只能查看历史」→ 它给你发过消息所以会话在，但本机没有它的地址：
   在「配对设置」里手填它的 IP 登记一下就好（登记完它才会出现在「＋ 新聊天」的候选里，也才能主动发）。

### 多台是怎么落地的（以前这一节是「得动哪些地方」的 TODO）

- `Hub.peers` 是 `HashMap<设备ID, Peer>`，一台一个条目；`Hub.active` 存的是**会话 ID**，只是会话栏的焦点，**不是**发送目标（目标由命令参数 `to` 给）。
- 会话表以 `Session.id` 为主键：基础对话 = 对端设备 ID，新话题 = UUID。`session_create(peer)` 只能建基础对话（重复点不会多出第二个框），
  `session_new(peer, name)` 开新话题（名字由前端按「设备名 · 月-日」给，撞名时后端加 (2)；返回的 `active` 就是新框 ID，少一次往返），`session_rename(id, name)` 只改本机那一份，
  `session_focus(id)` / `session_delete(id)` 一律按会话 ID 走。
- 心跳用 `std::thread::scope` 并发 ping 每一台，逐台算 `online` / `last_seen`；
  节拍是 `prefs.json` 的 `heartbeat_ms`（出厂 1 秒，可在「配对设置」抽屉的「设置」那一页 → 在线探测改成 2 / 5 / 10 秒，**每拍重读、不重启生效**）。
  `OFFLINE_THRESHOLD` 的口径不变（连续 3 拍探不通判离线：出厂 3 秒，选了 10 秒就是 30 秒）。设备数按 ≤8 台设计，不设上限。
- `/ping` 不再对未登记者回 409，而是无脑回 200：口令对不对由发起方比对 `device_id` 自己决定。
  那个 409 是「只支持两台」时代的遗留，副作用是把第二个实例自报的端口丢掉了。
- 零配置仍然成立，但**不再“先绑定的赢”**：心跳 ping 通一台就直接登记它（可发），不占会话焦点。
- 入向消息的 `peer` 取 `X-Device`，再按 `X-Session` 过 `resolve_incoming` 定下归哪个框（四条落点规则见第五节）；
  陌生会话是在这里顺手建出来的，否则那条历史没人认领。
  收文件时先只算落点（`route_session`）给进度事件定归属，收完那一条才真正建框 —— 不该为一个没收完的传输先建会话。
- `msg_history(limit, before, session)` 是**先按会话 ID 筛、再定位游标切页**（先切后筛会让每页凑不满，游标还会串到别的框的历史上去）。
- 前端 `state` 按会话分组：每个会话 ID 一套 `stream/游标`（`state.cur` 也是会话 ID，不是对端 ID），心跳推的在线态由
  `syncRailFromStatus()` 按所属那台回填到它的每一个框，未读数只在 `sessions()` 里算（它要整读一遍历史，绝不能塞进每秒都可能推的 `status_json`）。
- 历史里的日期分隔线按**相邻消息**插，首屏 / 往前补页 / 新消息追加三处都要重算（`reconcileDividers()`）。
- 首次启动做一次迁移：`peers.json` 里每台各建一个基础对话、历史里露出的对端补在后头，读指针推到当下
  （免得第一次进来冒出一堆莫名未读）。老历史按它**当时落的 `peer` 值**分框：单台时期那个字段写的就是
  当时绑定的那台，所以基本正确；空值的进「未标记」那一行，只能查看、不能发、也不能删。
  ⚠️ `messages.jsonl` 原文不改写 —— 真实发送方无法回溯，不做猜测式修正。也正因为不改写，
  基础对话的会话 ID 必须等于设备 ID，否则那些没有 `sid` 的旧消息会找不到家。

## 七、几个反复踩过的点（改代码前先看）

1. **serde 字段一律 snake_case，不加 `rename_all`**。曾用 camelCase 序列化出 `dataUrl`，前端读 `data_url`
   拿到 `undefined`，表现是「图片解码失败」，排查成本极高。
2. **`input[type=file]` 在 WKWebView 里递出的 File 是 0 字节**（只能拿到名字/类型），所以选文件必须走 Rust 侧对话框。
   **paste 事件一样**：剪贴板里的文件/位图在 JS 里读不到内容，所以粘贴也只能在 Rust 侧读（clip.rs）；
   好处是拿到的是真路径，连文件夹都能粘。粘完把路径交给 `routeDrop`，跟拖拽走同一条下游。
3. **`hidden` 属性能不能生效取决于有没有 `.xxx { display: ... }` 盖住它**，style.css 里有一条
   `[hidden] { display: none !important }` 的统一规则，新增覆盖层时别再写高优先级的 display。
4. **拖拽遮罩必须 `pointer-events: none`**，否则会把 Tauri 原生 drag-drop 的 `drop` 事件吃掉。
5. **切视图时的 `clientWidth` 是 0**，隐藏期间不能做 fit 计算，要等 `onViewChange` 回来再重量一次。
6. 界面异常优先看日志：Rust 侧统一 `eprintln!`（`[net]` / `[xfer]` 前缀），前端 `console` 带 `[view]` 前缀。
7. 收到消息的 `peer` 字段存的是**签名里那个 `X-Device`（真实发送方的设备 ID）**，会话就按它归类。
   伪造这个头过不了签名，所以它能直信。两个例外：旧版 UI 拿不到名字时只能用一截设备 ID；
   **单台时期落的历史不可信**（当时写的就是接收那一刻绑定的那台），无法回溯修正，所以首次迁移只能按现值分（第五节）。
   同一台的几个框再按 `sid` 分；`sid` 为空的旧消息全部默认归到那台的基础对话（它的会话 ID 就是设备 ID）。
8. **clip.rs 的 Windows 分支在 mac 上只能靠壳工程做类型检查**：正式工程的 build.rs（tauri-build → winres）
   交叉到 windows 时要资源编译器（llvm-rc），本机没有，直接 `cargo check --target x86_64-pc-windows-msvc`
   会在 build script 里 panic。`tools/clip-win-check/` 就是为了绕过这一层：它用 `#[path]` 把 clip.rs 原样
   include 进来，再补 store / net::server 几个最小桩，依赖版本与正式工程一致。同一套做法后来又多了一个壳：
   `tools/win-check/` 只 include `net/sound.rs` 与 `net/badge.rs`（这两个文件不需要桩，直接 `#[path]` 就够），
   它是在 CI 的 windows job 因为一个 `use` 路径报错挂掉之后补的（见 #35）：

   ```bash
   rustup target add x86_64-pc-windows-msvc
   cd tools/clip-win-check    # 或 tools/win-check（两个壳共用一个 target 目录）
   CARGO_TARGET_DIR=../../src-tauri/target cargo check --target x86_64-pc-windows-msvc --lib
   ```

   （共享 target 目录是为了重用已编好的 tauri 依赖，否则一次要重编几分钟）。
   这一步只保证能过类型检查，真正装包仍然只能靠 CI 的 windows 产物与实机验证。
   壳里那句 `#![allow(dead_code)]` 不是多余的：正式工程里 `first_existing` / `should_play` 这些由
   server.rs 调，而壳只 include 这两个文件，不 allow 就会一堆 never used 告警把真问题淹掉。
   想知道某个 `#[cfg]` 门控能不能拆（比如 MAC_SOUNDS），就得临时把这句 allow 注释掉再跑。
9. **粘进来的图“显示不正常”，先查剪贴板再查代码**：源程序往剪贴板里放的可能就是它给这个文件画的
   **占位图标**（实测过一张 1024×1024 的“JPG 文档图标”位图，微信未下载完的图、云盘在线文件、
   网页里加载失败的 img 都是这个形状）。我们原样存进 pastebox，看上去就是“图错了”，其实链路全对。
   排查时靠只读探针（第六节）或 `osascript -l JavaScript` 列 `NSPasteboard.types` 看剪贴板内容，
   只看到 `public.png`/`public.tiff`、没有 `public.file-url`，
   说明源既没给路径也没给真图，改代码救不回来。
10. **Windows 的复制出口只挂了 CF_HDROP（文件），没挂图片位图**：mac 那份 PNG 是 NSBitmapImageRep
    现算的，Windows 要 CF_DIB 得走 WIC 解码，目前没有实机可验所以没写。
    影响：从我们 app ⌘C 出去再粘到 Windows 侧某些只收位图的目标会拿不到图（微信 Windows 版粘图文件会当文件发）。
11. **`public.file-url` 有两种给法**：有的来源只把它当**数据**写（`stringForType:` 返回 nil）。
    只读 string 的写法会把这种剪贴板误判成「没有文件」，退回去存那张**文件图标位图**，
    症状就是“粘出来的图永远是一个 JPG 文档图标”。现在 string 拿不到就按 UTF-8 解 data，
    两条路都空再兜一次 pasteboard 级的 `public.file-url`；备料用 `onlyfileurl.js`。
12. **微信网页版里“以文件形式发送的 JPG”，复制到的就是那张占位卡片**（实测）：
    浏览器里那张卡片本身就是一张 1024×1024 的图，⌘C 出去的就是它，
    跟本应用无关。判据：收到的文件名长成
    `_cgi-bin_mmwebwx-bin_webwxgetmsgimg__&MsgID=…&skey=…&mmweb_appid=wx_webfilehelper.jpg`。
    正确做法：先把文件**下载到本地**，再拖文件进窗口（或选中文件 ⌘C 后粘，走 file-url 分支拿原路径）。
    人肉判断口径：文档图标是“正方形 + 带 alpha + 四角全透明”，真照片与截图四角不会透明
    （实测：占位图 1024×1024 四角 alpha 全 0；真图 1234×1062 与截图 1059×549 四角均不透明）。
    程序里不再做这个自动识别（排障期加的 `looks_like_file_icon()` 与 `clip-note` 提示已拆）。
    **但先按 #14 排除“我们自己把有效 file-url 丢掉了”的情况** —— 四角透明的图标
    并不一定就是源的锅。
13. **早期版本会把收件箱消息的 `path` 按名字长度硬截**（还会削掉 `.jpg`），
    文件其实就在同一个目录里、只是名字更长，于是前端每次展开都报“缩略图读取失败”。
    现在启动时会跑一次 `Store::repair_inbox_paths()`：只认“名字≥ 100 字符 且
    同目录下恰好只有一个文件以它为前缀”这一种窄情形，找回就补写一条修正记录
    （JSONL 后写覆盖前写），幂等、不会把历史堆长。
14. **Finder 复制的文件，`public.file-url` 可能不是路径而是「文件 ID」**（本条才是“粘出来
    总是那张文档图标”的真凶）：长这样的 URL 直接取 path 会得到一个不存在的位置，
    于是被误判成“剪贴板里没有文件”，退回去存了随附的 `com.apple.icns` 图标：

    ```
    file:///.file/id=6571367.105483633
    ```

    认这种来源的特征：剪贴板类型里同时有 `com.apple.finder.noderef` / `fndf` / `com.apple.icns`。
    两层修法（`clip.rs`）：`resolve_id_url()` 走 `NSURL.filePathURL` 把 ID URL 转成真实路径；
    转不动再兜一层 `nsfilenames_paths()` —— 把已废弃但 Finder 仍在写的 `NSFilenamesPboardType`
    （一份字符串数组 plist）用 `NSPropertyListSerialization` 解出来。
    验证：只读探针在真实现场上拿到了完整中文长路径（`/Users/…/详情_13_副本2.jpg`）。
    注意：转完就是现成的文件系统路径，**不能再走一遍百分号解码**，否则中文会被拆坏。
15. **“点了 B 却粘进 A”：两层叠加的坑，只修一层不够**。
    第一层：单击空窗那条传了 `pane.key`，进的是点的那个窗；而全局 `⌘V` 走
    `routeDrop(paths)`，**不携带落点**，`registerDropHandler("compare", …)` 拿到
    `paneKey === undefined` 就退回 `fillPanes(paths, null)` —— 而它从第一个空窗开始铺，于是永远就是 A。
    第二层（只修第一层时会残留）：空窗单击处理里 `if (pane.loaded) return;` 写在最前面，
    **点一个已有图的窗格时连“选了哪格”都没记**，于是 ⌘V 依旧拿不到目标。
    定稿（`view-compare.js`）：`panePicked` 与 `activePane` **分开记**（`assign()` 也会改
    `activePane`，光靠它分不清“用户选的”还是“刚被自动铺上的”）；单击先 `setPicked(pane)`
    再判断是否空窗；`pasteTargetKey()` 优先给 `panePicked`（**已有图也照换**，换掉就是点的意图），
    被布局切走或从未点过才退回“第一个空窗”；拖拽有真实落点时仍按落点。
    选中格原先描一圈蓝边（`.viewport.is-picked`）；**那圈边已按用户要求拆掉**（压在图上太抢眼），
    类名仍挂在 DOM 上当 devtools 标记，路由靠 `panePicked`，与样式无关。
16. **算“图片”的扩展名有三份表，加一种格式必须一次改齐**：Rust 的 `IMAGE_EXTS`（`list_folder_images`
    的目录过滤与 `pick_images` 对话框的 filter 都用它）、`lib.rs` 的 `mime_of()`（认不出就回
    `application/octet-stream`）、前端 `api.js` 的 `IMAGE_EXT`（粘贴、外部打开、侧栏的二次筛共用一份）。
    不齐的症状很隐蔽：侧栏列得出这张图、点进去却报「解码失败」（tif/tiff 就是这么补进来的）。
    `tools/folder_browse_check.mjs` 里「tif 也认（三份表必须一致）」与「后端漏进来的非图片会被前端
    再筛一道」两条专门盯这件事。
17. **「哪些窗可见」只有一个口径：`LAYOUT_KEYS`，而它必须与 CSS 的 `body.layout-N` 类同改**。
    可见性在两处各自表达：JS 里 `visiblePanes()`（同步广播、找空位填充、粘贴落点全问它），
    style.css 里靠 `body.layout-1/2/4` + `.only-multi` / `.only-grid` 准入类控制显隐。只改一边
    的症状很难查：要么图窗在 DOM 里可见却进不了同步组，要么反过来 —— 一个看不见的窗接收了
    `⌘V`，用户只觉得「粘不上」。`body` 默认就是 `layout-2`（HTML 里写死）而不是靠 JS 加类，
    否则首帧会闪一下。`tools/prefs_layout_check.mjs` 第 9 节专门核这份合约（假 DOM 不解析 HTML，
    所以那一节是对源码做字符串核对，而不是跑事件）。
    **准入类如今只剩窗体自己用**：`#pane-b` 带 `.only-multi`、`#pane-c/d` 带 `.only-grid`。
    工具栏（「打开 A/B/C/D」已拆）与状态栏（四个窗的信息行已搬进窗里，见 #21）都不再需要准入规则 ——
    留着不删不会报错，但下一个人会照着它再开一个「只能露一半」的入口出来。
    **这条口径真的在 2026-10-26 那次三档重构里被破过一次**：`.only-multi`（B 窗）的显示规则只写了
    `body.layout-2`，4 图档没写，于是 2×2 网格里只放得下 A/C/D 三个窗、第四格空着（DOM 里没这个窗，
    连棋盘底与空态提示都没有），而 `LAYOUT_KEYS[4]` 依旧包着 `b` —— 浏览交替把下一张送进那个不存在的
    窗，用户看到的就是「图载入了却展示不了」。**更糟的是自检里那条合约把错的口径当正确钉住了**
    （原文就写着「B 窗只在两图出现」）—— 合约写反比没合约更危险，因为它会让下一次改动主动去维护这个 bug。
    现在改成把两份口径都从真文件读回来逐档逐窗**双向核**（`LAYOUT_KEYS` × CSS 准入类 × HTML 窗体），
    并把那条对称地写成「B 窗在 2/4 两档都要在」；已负向验证：删掉 `layout-4` 那条会红，还会精确打出
    「对不上：layout-4 窗 b（CSS 藏 / JS 可见）」。
18. **「工具栏一个开关、设置里又一个开关」这种需求，联动要拆成「镜像」与「动作」两件事**：
    程序化地改 `checkbox.checked` / `select.value` **不会触发 change 事件**，所以互相回填不会自己转回去，
    但也意味着镜像那一半不会顺手执行动作 —— 每个入口都得自己把「改取态 + 执行动作 + 存盘」三件事写全。
    另外这枚开关是**真 `input` 藏在 `label.switch` 里**（`input` 本身 `display:none`），光靠 `:disabled`
    看不出任何区别，得给外层 label 另挂一个 `.is-disabled`（含 `pointer-events: none`），
    并靠 `chk.closest(".switch")` 找到那一层。
19. **存盘只看「真的改了吗」**：`setLayout()` 返回布尔，调用方（三档按钮 / 抽屉下拉 / 快捷键）写成
    `if (setLayout(k)) savePrefs({ layout })`。无条件存盘的话，重复点当前那一档也会写一次盘。
    非法值同理：前端 `LAYOUTS.includes` 先拦下（比丢给后端报错更严，磁盘上永远不会有非法布局），
    但拦下后必须 `refreshLayoutUI()` 把下拉取态拉回真实那一档，否则控件会停在一个界面根本没进入的档位上。
20. **“选中即显示”之后，重复指向同一行的入口必须短路**：侧栏的入口从“只有点行”变成了“点行 + ↑↓ + Home/End + Enter”，
    同一个 `browseTo()` 会被重复调到同一行。不拦住的话两图下会“把同一张塞进对面窗”（症状就是莫名多出图），还白读一回盘。
    判定不能只看游标 `browse.idx`，要同时比对**可见窗**里的 `p.meta.path`：中途手动换过图、或那张推到了隐藏窗，
    游标都是陈的，此时必须重新读一次。

21. **每个窗的信息就该住在自己那个窗里**：四个窗的「文件名 · 分辨率 · 体积」原先挤在窗口底部
    那条共用状态栏（`.statusbar`）里，两个毛病：一排平排四列时宽度不够，只能裁成「2048×…」；
    而且对不上是哪一格的数。现在每个 `<section class="pane">` 底部多一行 `.pane-foot`（id 仍是
    `st-info-a/b/c/d`，`refreshStatus()` 一行没改），宽度天然跟着窗走，也就自然跟着分隔条与网格列宽变。
    搬进窗里还顺手把 #17 那个「准入必须与窗同档」的问题消灭了 —— 脚注在窗内部，窗藏了它跟着藏，不再需要准入类。
    构造上的两个必需项：`.pane` 要从横向 flex 改成 `flex-direction: column`（`.pane-tag` 是绝对定位，不受影响），
    并且给 `.viewport` 补 `min-height: 0`，否则画面会把脚注顶出窗外。

22. **列表里的名字要从中间裁，不能只靠 CSS 的末尾省略号**：文件浏览器的名字往往是「公共前缀 + 随机尾巴」
    （UUID、微信哈希、`..._2K_20261025150443.jpg` 这种带时间戳的生成图），末尾省略号恰好把**区分点**和扩展名
    一起切掉，两行看着完全一样。所以显示前先用 `shortName()` 压到 `STRIP_NAME_MAX` 个字符：保住开头一半、
    尾部一半与末尾那段扩展名（只认点后 ≤ 8 字符的，`image.png_2K_xxx.jpg` 这种点在中段的也能认对），
    CSS 的 `text-overflow` 降级成窄侧栏下的最后一道保险。裁的只是那一行显示文本 ——
    `title`、`dataset.path`、排序、落盘路径全部用完整名，不然悬停与后续定位都会错。

23. **侧栏那 190px 以前根本没生效**：`.filmstrip` 写的是 `flex: 0 0 190px`，但它是 flex item 而 **flex item 默认
    `min-width: auto`**，里面 `.fs-name` 又是 `white-space: nowrap` —— 于是侧栏的自动最小尺寸等于
    「最长那条名字不换行的宽度」，190px 被撑到几百 px，名字多长都完整显示，CSS 的省略号永远不触发。
    症状上看不出错（不报错、不错位，只是宽），只能从「为什么定宽栏里的长文本从不被裁」这个角度反推。
    修法是给 `.filmstrip` 补 `min-width: 0`（与 `.fs-main`、`.cmp-body` 上已有的那几条同一个道理）。
    **同一个坑的第二个症状**：修完之后名称列真的只剩 ~102px 了，`shortName()` 若还按 24 字符裁，
    会被 CSS 末尾省略号再补一刀，恰好把中间裁切想保住的扩展名砍掉 —— 所以上限要按**列实宽**定（16），
    并把 `.fs-name` 降到 12px 让这 16 字符刚好放进去。两条都已入合约断言（`prefs_layout_check` 第 9 节）。

24. **「一个 item 挂两味」不能写成「两个 item 各挂一味」**：⌘C 复制一张图出去会变成两张一模一样的图，
    原因在 `clip.rs` 的 `copy_as_file`：它把 NSURL 与一个只带 `public.png` 的 item 一起交给
    `writeObjects:`，而 **`writeObjects:` 是一个对象一个 pasteboardItem** —— 剪贴板里于是有 2 个 item。
    只认第一个表示的应用（微信聊天框、Finder）看起来完全正常，**逐项粘**的应用（Word / 备忘录 / Keynote）
    会把文件与位图各插一张，看起来就是「复制出来两张同样的图」。
    修法是把两味合并到**同一个** `NSPasteboardItem`（`public.file-url` 的数据就是 URL `absoluteString` 的
    UTF-8 字节，`public.png` 直接 `setData:forType:`），解不出位图时才退回纯 NSURL。
    **为什么原来的自检没发现**：`osascript` 列的是 pasteboard 级的 `types`，它把所有 item 的类型拉平去重，
    两味分在两个 item 上时看起来完全一样。所以探针（`clip::real_clipboard::真机剪贴板探针`）现在直接
    `dump_items()` 数 item 个数，并**回读一次**确认合并后文件那味仍解得开（我们自己读剪贴板走的也是 `public.file-url`）。
    另一件同症状的不同事：`copyTargets()`（⌘C 拿哪几张）以前不去重，同一张摆在两个窗里时会把同一条路径
    复制两遍，粘出去也是两张一样的图 —— 现在过 `new Set`，第 14 节看着这条。

25. **「解绑」得配一份名单，否则只撑一秒**：症状是点了「解绑当前对端」，几秒后那台又自己连上了。
    原因不在解绑那一下，而在心跳线程（`client.rs::spawn_heartbeat`）：它每秒把**所有还没登记的 mDNS 候选**
    都 ping 一遍，ping 通就 `bind_peer` 自动登记 —— 而 mDNS 不会因为本机解绑就停止广播，那台依旧在候选里。
    所以解绑时要把设备 ID 记进 `peers.json` 的 `ignored`（与 `sessions.json` 里那份 `hidden` 同一个思路），
    心跳的候选过 `auto_bind_targets()` 时同时排除「已绑的」与「解绑过的」。
    **名单必须落盘**：只在内存里拉黑，重启后 `Hub::new` 什么都不知道，那台又被自动登记回来了。
    两个口径得跟着对上：① 它仍然留在「已发现」候选里（要恢复只能用户亲手点，但得看得见），
    候选按钮上标一句「已解绑」；② `bind_peer` 会把它从名单里拿掉 —— 手动 IP、点候选、重新探测
    都算用户亲手重新添加。另外 `startChat()` 里「先添加再开框」那一步原本写在 `have` 分支之后，
    于是一台**已有历史框**的解绑设备会被直接开出新框而跳过添加，变成一个永远发不出去的框 —— 现在提到最前。

26. **对端备注名（像微信那个）：口径只有一份，而且不能上线**：`Peer.alias` 只存本机，
    空串 = 没备注。显示一律走 `Peer::display_name()`（备注 > 对方报的名 > 露一截设备 ID），
    前端 `peerLabel()` 逐字抄的是同一个口径 —— 两边不一致就会出现「顶栏叫备注、会话栏叫设备名」。
    三个必须防住的坑：
    ① `bind_peer` 是**整条覆盖**，而对方 `/ping` 响应里根本没有 `alias` 这个字段，
    不从旧记录里把它搬过来，心跳每一拍都会拿对方报的名把用户刚写的备注顶掉（症状是「改完几秒就恢复原状」）；
    ② 备注改了但会话栏里还是老名字等于只改了一半：`set_peer_alias` 会把这台名下**还叫旧显示名**的
    对话框一起改名（`rename_by_display`），但用户自己改过名的框（「报销单」）与按日期起的名不能跟着动 ——
    那是他给这个框起的名字，不是一台设备的名字；③ 心跳每秒都可能推一次 `peers-changed`，
    备注框的回写要过三道判断：焦点在里面不动、框里是一份**未保存的草稿**（与代码上次写进去的那份不同
    且后端没变）也不动，只在「换了那一台」或「后端那份真变了」时才回写 —— 只判 `document.activeElement`
    还是不够，用户点去别处一下草稿就没了。
    老 `peers.json` 少 `alias` / `ignored` 两个字段都靠 `#[serde(default)]` 兜着，不会整个对端列表读不出来。

27. **离线排队补发：几个看着很自然、其实会错的做法**。「对端离线也能发」的地基其实全在现有那几条
    性质上（`messages.jsonl` 追加写 + 同 id 以最后一条为准 + 保持首次出现顺序；前端 `upsertMessage` 对已存在
    id 只改状态不移位；入向文字存的是 body 里带的 `ts`），所以**协议一行不用改**。难点在以下几个选择：
    ① **补发不能只挂「离线转在线」的边沿**：重启后第一拍心跳才会把 `online` 从默认的 false 翻成 true，
    解绑后首拍又会假翻一次 —— 只靠边沿要么漏投、要么白投。现在只挂**一个**周期触发点（心跳循环末尾
    `spawn_due_flush()`，队列空就直接走），同一条路径兼顾「重启」「上线」「上次没投完」。
    另外入队后得当场 `spawn_flush` 一次：对方其实在线、只是 `last_seen` 陈着这一拍很常见，
    让用户等下一秒会看着像「排队排错了」。② **`retry` 计数必须落盘**：只在内存记的话重启就归零，
    一个发不出去的大文件夹会被无限重传；上限 `MAX_RETRY = 3` 转 `failed`，而「路径已经不在了」
    这类硬错误一次就停（重试三趟只会白跑）。③ **文件队列只存本机路径、不做内容快照**：
    复制一份进 `pastebox` 会占双份磁盘，而且收件箱会落一个用户以为早删掉的旧版本；
    文件夹也不预先展开，**补发那一刻才递归**（排队期间它可能又被塞了几张）。④ **一个对话框一次只容
    一个投递者**（`Hub.flushing`）：否则同一队列会被两个线程各读一份、投两遍且顺序交叉；
    分组一律按 `sid_of()` 而不是按 `peer`，否则同一台两个框会互相插队。⑤ **未配对不进队列、
    解绑不动队列**：解绑只是不再主动连它，那台被亲手加回来时这几条还得接着投；会话被删了则把
    它那几条标成 `failed`（理由写「这个对话框已经被删了」），而不是默默吞掉。⑥ **补发文件时 batch id 必须复用
    待发气泡自己那个 id**：进度事件带的是 batch id，前端拿它找气泡；另造一个 UUID 就找不到，而它找不到时
    会先占一个「接收中」的**入向**气泡 —— 自己发文件却凭空多出一个对方发来的气泡（直发那一路本来就是
    id = batch，所以两条路必须对齐）。
    本次真踩到的一个坑：**「只筛含 `queued` 的行」不能当去重前的快筛**。一条补发成功的消息是先写
    `queued` 再追加同 id 的 `sent`，只看含 `queued` 的那些行会把 `sent` 那行滤掉，于是这条早就发出去的
    消息永远赖在队列里反复重投 —— 现在只在「整个文件一行 `"queued"` 都没有」时走快路径，
    否则老老实实拿 `dedup_lines` 按**全部**行去重再看状态（这个 bug 是先被单测抓到的）。
    测不了的那一半（线程循环、真网络）全抽成了纯函数：`classify_target` / `flush_targets` / `retry`。

28. **放大层的缩放：存哪个数、拿哪个盒，都不能错**。看着就是「给一张图加个 transform」，但几个选择
    一旦选错就是那种跑起来才发现、而自检还是全绿的错：① **状态存的是「渲染宽 / 原始宽」（1 = 100% = 原始像素），
    不是 transform 的倍数**。CSS 已经先把图装进屏幕（`max-width: 92vw`），而这一档会随窗口变：直接存
    倍数的话， resize 之后要么图不再 100%、要么百分比标签说谎。存原始口径，transform 只需除以
    打开时量到的那一档（`fit`），而 `fit` 在重开 / resize / 解码完成后都会重量。② **锚点公式与 CSS
    `transform-origin: 0 0` 绑死**（公式推的就是「屏幕 = 盒左上 + 平移 + 倍数 × 盒内坐标」，与对比视图
    的 `applyZoom` 同一个式子）：谁把原点改回默认的 `center`、或把公式抄成另一种形式，锚点会整片跑掉，而
    **假 DOM 不做布局，行为自检根本看不出来** —— 所以 `prefs_layout_check` 拿静态合约钉住了
    `transform-origin` 与绝对定位的控件条（控件条一旦参加 flex 布局，就会把居中的图顶上去，同样是看不出来的偏）。
    ③ **盒必须在「transform 还是初始值、平移为 0」那一刻量**：transform 不改布局，所以打开时量到的
    未变换盒整层开着期间都有效；开晚一步（已经缩放过）拿到的就是变换后的盒，锚点全歪。④ **`naturalWidth`
    要解码完才准**：同一份 data URL 通常已经在缩略图上解好了，但大图解码未完时量到 0，拿它做除数就是
    Infinity；所以量不到就退化成 `fit = 1`，并在 `load` 后补量一次 —— 而且**用户已经动过就不抢**
    （别把他正在看的细节拉回适应）。⑤ **拖完那一下的 click 要整体吃掉**：松手时鼠标已经不在图上，
    事件目标会落到背景，而「点背景 = 关层」是现有行为；不吞这一口就会「刚拖完图一松手层没了」。
    ⑥ 平移要**有个夹取（图中心留在视口内）**，否则 800% 下拖到全黑除了重开无解；但夹取不能做进
    锚点公式里（那会让「指针下的像素」不成立），所以只做在渲染前的平移量上。⑦ **控件条必需要自己的
    `z-index`**：图本来是个静态元素，本来是压不住绝对定位的控件的，但它一旦挂上 `transform` 就自成
    层叠上下文，绘制顺序改按 DOM 先后算 —— 而控件条与关闭按钮在 HTML 里都排在图之前，结果就是
    「放大后的图把按键整个盖住」（真机撞到的）。假 DOM **不做绘制**，叠放序这种事行为自检永远全绿，
    所以 `prefs_layout_check` 里除了 z-index 还钉了一条「HTML 里控件条确实排在图之前」（把顺序改成
    图在前、再拿掉 z-index 也能过，但那是另一种做法，不能两套都靠直觉）。

29. **田字平铺（拿同一张图铺四份看是否无缝衔接）：选错画法就是选了个会自己造假缝的工具**。
    这个功能判的就是「两条边之间有没有缝」，而用四个 `<img>` 拼田字时，非整数倍缩放下浏览器
    会在格子之间画出**亚像素亮缝** —— 那条缝是渲染造的，正好会被当成「图没接上」，把结论
    整个带偏。所以平铺走 `background-repeat: repeat`（格子之间数学上共边），几个连带决定：
    ① **不另存一套状态**：格子尺寸 = 单张在当前 `zoom` 下的渲染尺寸，十字交点 = 单张盒中心 +
    同一个平移量，所以滚轮锚点、拖拽、上下限、百分比那些一行都不用改，而且**单张↔平铺
    切换不跳视野**（两种画法就是同一套数的两次投影）。② **藏那张图用 `visibility: hidden` 不是
    `display: none`**：盒要留给 `lbMeasure` —— 平铺状态下改窗口尺寸还得重量「适应那一档」是多宽。
    ③ **平铺下不做平移夹取**：图案本来就铺满整屏、拖不到全黑，而拿单张盒中心去卡一个周期图案，
    会把「拖到隔壁那条缝」错拦下来。④ **背图只在换图时写一次**：那串 base64 可以很大，滚轮每帧
    重拼字符串会卡；关层时连同 `img.src` 一起抹掉，不留一份解码完的大图常驻内存。⑤ 平铺时鼠标
    落在画布上而不是那张（被藏起来的）图，所以双击与拖拽两个手势**绑到两个面上**（同一个函数）；
    代价是整屏都是画布，`ev.target` 永远命不中背景，「点背景关层」自然失效（退出靠 × / Esc / 再按田）。
    ⑥ **id 不能撞车**：写第一版时「田」按钮与画布都叫 `lightbox-tile`，真浏览器里 `getElementById`
    只拿第一个（按钮点不到、画布拿不到），而桩里的 `byId` 是按名字各自造元素，行为自检全绿；
    所以 `prefs_layout_check` 里钉了一条「index.html 里 id 全局唯一」的全局合约。

30. **侧栏行拖到图窗：项目里做不了 HTML5 拖拽，而「拖完那一下 click」是个会漏的东西**。
    ① **`draggable` 在这个项目里直接用不了**：`dragDropEnabled: true`（外文件拖进来靠它）下 macOS 会把页面内的
    HTML5 拖拽当原生拖放会话拦掉，那条通道只递路径。对比视图里早就有一句
    `if (isTauriRuntime) return; // Tauri 下由原生拖拽事件接管`，说的就是同一件事。所以这趟全程指针事件，
    浏览器与 Tauri 表现一致，还能进假 DOM 自检（真 HTML5 DnD 桩里根本没法派事件）。
    ② 跟手那枚牌两个地方不能省：`pointer-events: none`（它就在指针底下，不屏蔽鼠标事件就会把自己
    当成落点，永远命中不到窗），以及 `[hidden] { display: none !important }` 那条全局规则 —— 牌自己写着
    `display: flex`，class 与 attribute 权重相同，没那句 `!important` 它就开场即露。两条都在
    `prefs_layout_check` 里钉了静态合约（假 DOM 不解析 HTML，看不见这些）。
    ③ **拖与点是同一个 `mousedown` 分出来的两件事**：没超 4px 就还是一次点行（不能 `preventDefault`，
    否则那个 click 就没了）；超了就要挡掉紧跟的 click —— 而且这个标记**得在“真的起拖了”那一刻设，
    不能只在成功落窗时设**：第一版就漏在松手落在侧栏里那一趟（没命中窗 → 不设标记 → 浏览器补的 click
    把刚作废的一页又翻了出来）。改成起拖就记、下一次按下复位，才不会多吐一次正常点击。
    ④ **异步载入的断言不 `settle()` 就是空断言**：「拖完的 click 不吃浏览」那条第一版没写
    `await settle()`，把 guard 整块删掉它照样绿（browseTo 还在 promise 里，src 还没变）；做了负向验证才发现，
    补上 settle 后同一处变异能敲出 3 条 FAIL。另两个变异（`paneAtPoint` 改成遍历 `PANE_KEYS`）则由
    「松在没有可见窗的地方：什么都没发生」接住 —— `fillPanes()` 自己那道「目标窗不可见就改填可见窗」
    的守卫也在那条里一并验了。
    ⑤ 落点命中用新的 `paneAtPoint(x, y)`（鼠标事件已是 CSS 像素），**不要混用 Tauri 那个 `paneAt(position)`** ——
    那个还要猜一轮物理/逻辑像素，拿给鼠标事件用会算错。

31. **侧栏缩略图改走 `asset://`：三处必须一起改，缺哪处都是「整片空白」，而且只在真机上出现**。
    ① 这件事的根因不是 bug：早期只做「当前项 ±1」是**刻意闸门**（Rust 不带 `image` 依赖，`read_image` 回的是
    整图 base64，一个目录几百张不可能全读），所以用户看到的「只有旁边两张有图」是设计如此。要变成整列都有图，
    只能换通道，不能靠调常量 —— 调大窗口等于把内存闸门拆了。
    ② 新通道是 `convertFileSrc()`：图直接指本地文件，缩放与解码交给 WebView，**一个字节不走 IPC**，
    svg/avif 这些 `read_image` 解不了的也就能显示了。但它要**三处同时到位**：
    `js/api.js` 的 `assetSrc()`（取地址 + 取不到就回 null）、`tauri.conf.json` 的
    `app.security.assetProtocol`（`enable` 与 `scope` 缺一不可，只开协议不给范围照样取不到文件）、
    以及 CSP 里 `img-src` 收得下 `asset:` 与 `http://asset.localhost`（漏了这条，WebView 直接拦掉请求，
    控制台外一点痕迹都没有）。`scope` 是 JSON，写不了注释，口径写在第八节那张表下面。
    ③ 三处的取值/键名假 DOM 桩里全看不见，所以在 `prefs_layout_check` 里钉了 8 条**静态合约**
    （直接读 `tauri.conf.json` 与 `api.js` 的源码比对），并把「`ensureThumb` 里 asset 分支必须排在 LRU 与
    ±1 闸门之前」也钉住 —— 排在后面就会被窗口闸门拦回三行，且测试里很难看出来。
    ④ **退路一条没删**：`assetSrc()` 回 null（纯浏览器里调试、或 `convertFileSrc` 抛错）就走原来的
    `read_image` + 三道闸门。因此改完那四套自检仍然全绿 —— 但「全绿」不等于新分支被验到了，
    于是第 16 节另配 asset 用例，并把两套口径各自钉住。
    ⑤ 负向验证在这里咬出了两个**看着绿其实什么都没验**的断言：asset 用例起初借用了前面章节碰过的
    `GAMMA` 目录，LRU 里那些整图还在，于是「一次 IPC 也不发」退化成缓存命中照样成立；把 asset 早退整块
    删掉它仍绿。改法是给 asset 段与退路段各配一个**前面谁都没碰过的干净目录**（`DELTA` / `EPS`），
    并且除总数外再单独盯一张「落在老窗口里」的图 —— 它在退路下必然被读一回，asset 模式下必须是零次。
    另一条同类问题：退路段借用 `GAMMA` 时，「窗口外的行不读」其实是 LRU 命中画出来的，全靠容量 8 恰好被挤干净，
    属于随时会翻脸的用例。教训与 #30④ 是同一句：**断言要么能变异出红，它就不存在。**

32. **scope 里写错 glob 是「启动就 panic」，而 asset 拿得到地址不等于拿得到文件**（上一条的两次续集）。
    ① `assetProtocol.scope` 用的是 `glob::Pattern`，它**只把当前平台的分隔符当路径段**：macOS/Linux 上
    `\` 不是分隔符，所以 `C:\Users\**` 里的 `**` 不算独占一段 → 报错 `recursive wildcards must form a single
    path component`。恶劣之处在于它**不在任何静态检查里报**：JSON schema 能过、`cargo build` 能过（配置只在
    `Builder` 运行时才编译 glob），症状是启动直接 panic。
    ①′ 盘符**不要枚举**：`C:` `D:` `E:` 这种写法永远在补漏（F/G/网络盘都会中），而且 glob 只认当前平台
    的分隔符，`/**` 在 mac 上实测（拿 glob-0.3.4 跑的）根本匹配不到带盘符的路径。现在的写法是一条 `**` 兜住
    所有盘 —— 它匹配任意多个路径段，因此不管 `C:\Users\...` 还是 `is_allowed()` canonicalize 后的
    `\\?\C:\...` 都在范围内。代价说清楚：`SafePathBuf` 只拦 `..`、不拦相对路径，所以 `**` 比 `/**` 确实宽
    （连相对路径形态也收），但这个工具早就有不做范围检查的 `read_image`/`read_folder` 自定义命令，边际风险很小。
    这条也钉了合约：scope 里必须含 `**`，且不得出现 `^[A-Za-z]:` 开头的枚举。
    ①″ 启实例验证时，看的是日志里有没有 `[net] 接收服务已监听`：scope 的 glob 在 `setup` 钩子**之前**编译
    （反例里 panic 先于这一行、整条 `[net]` 日志一行都没出），所以这行出现就等于 glob 过了。
    ② 这类「只在启动时爆」的配置拿假 DOM 看不见，所以 `prefs_layout_check` 里用 JS **复现了 glob 那条规则**
    （不含 `\`、无 `***`、每个 `**` 独占一个 `/` 段）—— 把一条启动期 panic 前改成一条测试失败。
    ③ **`convertFileSrc()` 返了地址不代表取得到文件**：scope 没覆盖、文件被取走、Windows 上 `is_allowed()` 前会
    `canonicalize`（得到 `\\?\C:\...` 这种 verbatim 路径，能否与 glob 对上本机无法验证）都只会让那张图
    `onerror`。所以「`assetSrc()` 回 null 才退路」是漏的：回不了 null、但图是破的。现在给 asset 图都挂了
    `onerror` → 抹掉破图并走 `read_image`；同时 `assetDead` 只认一次（第一张打日志，后面的行各自自愈但
    不再刷日志、也不再新挂 asset），否则会变成「每滚一回视口就多一次失败请求 + 一行日志」。
    只治第一张也不行（每张的 error 是各自报上来的），这一点第 17 节两条断言分开钉着：窗口内的行被重读、
    窗口外的行退回老口径就空着（**自愈不能顺手把内存闸门拆了**）。

33. **图标角标的 API 不会自己跳主线程，而底下的 tao 用的是 unchecked 的主线程标记**。
    `set_badge_label` / `set_overlay_icon` 从接收服务那个后台线程直接调是未定义行为（不保证崩，
    只是运气不好才崩，所以比崩更难查）。两条合法路径：后台线程一律走 `Hub::emit_sessions()`，
    由它包好 `run_on_main_thread`；能直调的只有 `app.run(...)` 的事件回调（那个回调本身就在主线程
    上跑，lib.rs 里关窗清零就是直调）。这一层包与不包在假 DOM 与单测里长得一模一样，
    所以 `prefs_layout_check` 拿静态合约盯着「`apply_badge` 必须出现在 `run_on_main_thread` 的闭包里」。
    同一个 API 族另一半坑是平台能力不对称：`set_badge_count` 在 Windows 直接 Unsupported，
    Windows 只给了 `set_overlay_icon`（能贴图标、显不了数字），而 `set_badge_label` 只在 mac 存在（
    都是 `#[cfg]` 门控的）。所以 badge.rs 里三个分支各自 `#[cfg]`，包 `overlay_dot()` 那两条必须一起
    门控，否则 mac 上就是一个 dead_code 告警（本仓要求 0 warning）。

34. **提示音只能在 Rust 侧响：wry 没放开自动播放，而「非用户手势」的媒体 WKWebView 一律拦**。
    ① 依据是读源码得到的（本机还没真机撞过）：`wry-0.57.1/src/wkwebview/mod.rs` 里只设了
    `allowsInlineMediaPlayback`，**没设** `mediaTypesRequiringUserActionForPlayback`，而那个属性的 WebKit 默认值是
    「音视频都要用户手势」。于是 `new Audio(...).play()` 由后端 push 的事件触发时（那一刻没有手势）会被拒成
    `NotAllowedError`。加上 macOS 关窗不退进程、前端根本不在场，「收消息响一声」这件事没有第二种做法。
    ② 同一族的判断口径以后照搬：**凡是需要在「用户没点我」的时候发生的媒体/弹窗**，得走 Rust（角标是同一族的先例，见 #33）。
    反过来也成立：只有用户手势才能干的（弹原生对话框、拷贝到剪贴板）才留在前端。
    ③ 声音本身必须带去重：`append_message` 只追加不去重，同一条 `msg_id` 被 retry / 离线补发再投一遍时，
    `read_messages` 靠「后写覆盖」看起来还是一条，而**声音会响两遍**。`Hub::last_notify` 存最近响过的那条 id，
    开关 + 同 id 两道否决都放在 `sound::should_play()` 这个纯函数里（单测直接测它，不靠真机听）。
    ④ 假 DOM 听不见声音、也不会解析 HTML 里那个 `checked`，所以这一套全靠 `prefs_layout_check` 的静态合约前移：
    出厂态三方一致（HTML `checked` / `default_notify()` / `Preferences::default()` 用的是同一个函数）、
    `set_prefs` 的参数名必须是单词 `notify` / `inbox`（#1 那条 camelCase 约束的续集：写成 `inboxDir` 不会报错，
    只会永远不生效）、`check_inbox` 三道闸齐、启动建目录不许再硬写 `dir.join("inbox")`、sound.rs 三个 `#[cfg]` 分支齐、
    两处落库各调一次 `notify_arrived`、两个新命令进了 `generate_handler`。这 20 条每条都做过负向变异（改坏必须变红）。
    ⑤ Windows 那一半的编译错靠 `tools/win-check` 在 mac 上就能抓到（#8），不等到推 tag。
    本机跑不了的是“听”：`MB_ICONASTERISK` 到底跟着谁的提示音方案走、系统禁了提示音时会不会
    把错误当成传输失败 —— 那两条归真机验收，不归编译器。

35. **windows 0.62 把 `MessageBeep` 归在 `System::Diagnostics::Debug` 页下，而参数类型仍在 `UI::WindowsAndMessaging`**。
    头文件上这是 user32 的函数，元数据里却不是按 DLL 分页的 —— 按直觉从 `WindowsAndMessaging` 引，mac 上一切正常
    （那个分支根本不参与编译），直到 CI 的 windows job 报 `E0432: unresolved import`。签名也不是旧文档里那套：
    参数直接吃 `MESSAGEBOX_STYLE`（不是 `.0`），返值是 `Result<()>`（不返 BOOL 让你手调 `.as_bool()`）。
    靠 `tools/win-check` 在 mac 上重编一遍就能拿到同样的报错，不必拿 CI 当编译器用（见第七节第 8 条）。
    另外两个细节：`Win32_System_Diagnostics_Debug` 这个特性目前是 tauri 传递过来的（不显式声明也能过），
    但自己 import 了就自己写上；`MAC_SOUNDS` 必须跟 `#[cfg(target_os = "macos")]`，否则 windows 分支就是一个
    never used 告警（本仓要求 0 warning）。这三条现在都有静态合约钉着。

36. **CI 的 windows job 挂了，Release 可能已经拿到了一半资产**。`build.yml` 里 `fail-fast: false`，
    mac 那条腿成功就会把 tgz 传上 Release（上传那一步在各条腿自己名下），windows 腿编译失败只让整个 run 变红，
    看起来就是「发版成功了，但只有一个包」。所以推完 tag 必须核 `releases/tags/vX.Y.Z` 的资产个数与名字，
    而不是只看 run 的结论；补发的话，那个残缺 Release 要么删掉重建，要么另起一个版本号
    （挪 tag 得先删远端 tag，属破坏性操作，要显式确认）。
    本次实测：run 结论 failure，Release 里只有 `image-compare-macos-arm64.tgz`，缺 `image-compare-setup.exe`。
    ② 更坑的是补发：删 tag 会连带删掉同名 Release，而这个级联是异步的、按 tag 名匹配的 ——
    它能在删除之后好几分钟才落地，于是把 CI 刚新建的那个 Release 一起吃掉。实测两次「删了重推同名 tag」：
    两个平台的 job 全绿、两步 `Attach installers` 都报 success（因为它写进了一个正在等死的 Release），
    结果 `/releases` 里始终没有 vX.Y.Z。所以：同名的 tag 只删一次、不反复挪；真要把包补上，
    优先另起一个版本号推新 tag（新 tag 不涉及删除，不会武装这个级联），或者等删除事件排空后
    在网页上对原 run 点 Re-run jobs（本机没 token 时只能走这两条）。

37. **应用图标要按 32px 反推，不能按 1024px 往下缩**。这一轮换图标，前两轮都是看 1024

    写死 12px 的滑杆线缩到 32px 只剩 0.4px，把手缩到 1.9px —— 最先消失的恰好是最核心的两个识别元素。
    定稿的三个修正：卡放到 74%、左半从暗石板提到中石板（更亮那档小尺寸最清楚，但已经不像图片类应用）、
    线宽一律按卡宽给比例；太阳只能待在左半（放中间会跟白线叠成两个白圆，放亮灰上又没对比）。

    已修并把「脚本必须写死源图路径」连同另两条一起进了静态合约；而 `tauri icon` 每次都会顺手多生成
    `src-tauri/icons/ios`、`android` 两套（本项目没移动目标），已进 `.gitignore`。

38. **历史只存 `path` 与 `seen`，不存 `name`/`size`**。存了就一定过期：改名之后侧栏写着老名字，
    体积那一格也是几年前的数字，而没有任何一处会去修正它。`name` 从 path 现算（`baseOf()`），
    第二格改用 `seen` 显示相对时间 —— 对「最近看过」这件事比体积有用。
    两源的渲染口径由一个 `stripMetaText(it)` 分流：`size === undefined` 就是历史条目，否则是目录条目。
    两个写单测时才踩得出来的事实（都已写进 `store.rs` 的注释）：`seen <= 0` 会被 `normalize()` 补成当前时间，
    于是那条反倒排到最前（测试数据拿它当「陈年旧值」就必然错）；`record()` 截断砍的是末尾，
    所以它的前提就是列表已经「新的在前」—— 调用方必须都出自 `load_history()`（那份刚 normalize 过）。

39. **一次读失败绝不能把那条从 `history.json` 里抹掉**。文件被移走 / 改名，症状就是那一行标灰

    都表现为「读不到」，自动删就等于替用户把他看过的记录清掉，而且不可回滚。

40. **切源不清 `thumbCache`，也不动 `browse.open`**。清 `thumbCache` 是「换目录」的动作，不是「换列表」：
    全文件只有 `ensureFolderList()` 里那一句（`prefs_layout_check.mjs` 有一条静态合约钉着「只有一处、
    且就在那函数里」），在 `applyHistory()` 里清的话，来回点一次那两枚 tab 攒下来的小图就全丢了，
    下一次 ±1 窗口又要回盘重读（`folder_browse_check.mjs` 第 18 节有一条专门盯总读盘次数，能照出来）。
    `browse.bad` 也不清：同一条僵尸路径在两个源里都该是灰的。开合同理 —— 侧栏开着还是收着是用户自己的事，
    `userClosed` 只在用户主动开关时才写，`setStripSource()` 全程不碰它。
41. **「真看到一张图」有两个出口，不是一个：`fillPanes()` 与 `browseTo()` 走的是不同的函数**。

42. **定宽列（`flex: 0 0 <N>px`）必须配 `min-width: 0`，否则长内容会把它撑破**。flex 项目的 `min-width`
    默认是 `auto`，下限就是内容的 min-content；会话预览里那种长文件名（`BJL261026010_E1082CAD…B6.jpg`）
    是一个不可断的整体，于是写着 `flex: 0 0 214px` 的 `.session-list` 实测被撑到 **367px**，
    而且因为宽度已经够，里面那行 `text-overflow: ellipsis` 全程不生效 —— 内部三层
    （`.s-main` / `.s-top b` / `.s-sub`）的 min-width 与 ellipsis 全做对了也没用，**病在容器那一层**。
    两个实测出来的边界：① 只需加在容器这一层（加在 `.session-rows` 上是冗余，对照实验证过）；
    ② 同样写 `flex: 0 0 232px` 的 `.tree`（收藏那棵树）**不会**撑，因为它自身带 `overflow: auto` ——
    auto 最小尺寸只对该元素 overflow 为 visible 时生效。所以判据是「定宽 + 自身无 overflow + 里面可能有长文本」
    三者同时成立才需补 `min-width: 0`，不要拿它当模板套到所有定宽块上。
    `prefs_layout_check` 里有一条**通用扫描**按这个判据扫全部 `flex: 0 0 <N>px` 规则
    （扫之前先剥注释，否则注释里写的 `min-width` / `overflow` 字样会被当成已防护而假通过；
    窄条与图位走显式白名单），另有一条直接钉 `.session-list`。
    **这类布局 bug 假 DOM 自检看不见**（它不解析 CSS），量法：把那一块结构原样复刻成一个临时 html
    （`<link>` 真实的 `js/style.css`），页里 `document.title = 量到的宽度`，再
    `chrome --headless=new --window-size=1200,800 --virtual-time-budget=3000 --dump-dom file://…`
    抓 `<title>` 就行（探针用完即删，不进仓库）。

44. **「田字查看」= 把这一张图原样铺成 2×2，验十字那两条接缝**（对比视图工具栏，快捷键 `T`）。

    没有同时显示 4 张图」。要检验的是这张图能不能像壁纸那样和自己接上：右边紧挨另一份的左边、

    恰好一次）；静态合约钉「源矩形是整张图 + 画布 `2w × 2h`」，这是第一版做反的直接回归位；

    屏幕上是四张一样的图、十字处没有亮线（那两张测试图四边留白，`SEAM_H` / `SEAM_V` 都为 0）。

    滚动条），控件条/关闭键/说明行直接复用放大层那三个类（`.lb-tools` / `.lb-close` / `.lb-cap`，

    的话底下的 `1`/`2`/`4` 会同时生效（按一个 `1` 两层一起动）；关掉时把 canvas 尺寸归零，那份
    `2w × 2h` 的位图是几十 MB。

54. **引用回复与转发**（2026-10-27 加）。两个入口都在气泡那份右键菜单里，**一条新命令都没加**：

      `Option<Quote>` + `#[serde(default)]` 让没有这个字段的行照读，serde 也不拒未知字段，所以

      验的就是「刚好留满 120 字再加一个省略号」）。
    - **两个入口的可见条件不一样，不要拼成一个**：引用不要求本机路径（接收中的文件也能引），
      转发那么「有正文」只对文字条算数、否则必须有路径（没路径转发过去就是个空包）。
    - **转发弹的是会话浮层而不是直接发**，列 `state.sessionList` 里除了当前那一格以外的所有框；
      点一条才走发送（所以下层菜单先收）。转出来的是全新 id 的新消息，两边各会话的
      撤回 / 删除 / 清空互不影响 —— 不标「原发送者」也是确认过的口径（收方看到的就是你发的普通消息）。
    - **叠层顺序得算上放大层**：放大层 z-index 900，`.fwd-pick` 940、`.ctx-menu` 950、`.find-pick` 960 ——
      都在它上面，否则点开大图中右键再选菜单项会弹出一个被图盖住一半的菜单。
    证据：`cargo test --lib` 83 → 85（`引用卡片跟着消息落盘且没引用时不占字段`：五字段往返、正文不被顶掉、
    全文里只有带引用那一行含 `"quote"`；`老行缺引用与看不懂的字段都读得开`：手写一行老格式 + 一行带
    `"将来的字段":7` 与只有一半字段的卡片 + 一行坏行，读得开、缺字段兜底成空串与 None、坏行跳过）；
    `session_route_check` 里那一组引用与转发判据（预览条默认收着 / 点引用后那条文案与摘录、× 取消、发出那一发
    带上了 quote、超 120 字截断加省略号、气泡上 quote-card 渲染与点击定位、原文没铺出来只提示不硬拉、
    菜单里「转发到别的会话」只给有正文或有路径的那几条、选人后 `send_text` / `send_paths` 的 `to` 就是选的那个框、
    浮层排除当前这一格）。放大层那一层另加 8 条（五项各自走哪个命令、在对比中打开先关层、
    菜单开着时点空白先收菜单不连带关层、没路径不拦右键、路径判定写在 `openLbMenu` 里）。跨文件合约钉住了
    `Quote` 两端字段对齐、`#chat-msg-menu` / `#xfer-fwd-pick` / `#lightbox-menu` 三枚 id 在 HTML 里、
    全中文无英文原生项、新 CSS 类（`.quote-card` 等）存在。

55. **清空一个对话框的历史**（2026-10-27 加）。用户口径是「保框删消息」：框还在、设备还在、
    对端那份与收件目录里的文件都不动 —— 与「删除聊天」的区别就写在那张表里（第四节），注释里也带了一份。
    - **`Store::clear_session(sid)` 是「一次全量读 + 一次整体重写」**，不是逐条 append：几百条历史逐条追一行
      就是几百行 IO 放大，而重写本来也不删行（仍然守住「只追加、不重写」那一条：写的是去重后的最新态 + 补上 `hidden`）。
      读的是整份文件去重后的**全部行**（`dedup_lines` 不做可见性过滤），否则「这一台看不见的」那些会漏标、下一次又冒出来。
    - **已 hidden 的不重复补写**，所以重复清一个清空的框回 0 条且**行数一行不多**（单测直接数行）。
    - **复用同一个 `hidden` 标记**（与逐条本机删除同源），所以 `read_messages()` 那一挡下去
      分页、摘要、未读、角标、全局搜索一起跟上，不新增任何特判；空串 sid 就是「未标记」那个筐（老消息 `sid_of()` 回退到 peer）。
    - **同一个菜单里两枚破坏性入口各自一枚臂**：共用一枚计时器会变成「点了清空又去点删除」互相臂上，
      手感也错（臂与计时器各一份：`railMenu.clearArmed` + `railClearTimer`，不跟「删除」那个 `railMenu.armed` / `railArmTimer` 共用，
      代码里那句话就是「臂不能互咬」）。
    - **清完的空态文案不能说「还没有消息」**：消息还在盘上，只是这一台不再显示 —— 那句与 toast 同一口径
      （「聊天记录已清空：对方那份与收到的文件都还在」）。
    证据：`cargo test --lib` 85 → 87（`清空聊天只把那一格标成不显示`：只动指定 sid、别的格与未标记筐不动、
    `raw_message()` 读回来 `hidden == true`、再清一次返空且行数不变；`清空聊天保住会话行也保住收进来的文件`：
    sessions.json 的 id/name/active/pinned 全不动、收件文件 `metadata` 还在、历史行一条没丢、撤回过的那条也被标上）；
    `session_route_check` 里那组判据（菜单有这一项、第一下只臂上、第二下 `session_clear` 的 `id` 就是右键那个框且只调一次、
    清前两条清后会话行还在）；`prefs_layout_check` 钉住了三段都在（store 的 `clear_session` 写 hidden → 命令层 →
    `generate_handler` 里那一行 —— 漏注册只会到真运行时才炸，node 桩里永远是绿的）。变异：
    `clear_session` 改成不判 hidden 只翻 `清空聊天只把那一格标成不显示` 那一条（已 hidden 的不该重复补写）。

56. **跨会话全局搜索（⌘F）**（2026-10-27 加）。与会话内那条小框**并存、不改它的语义**（那一边只筛已铺出来的）。
    - **新命令拆成两层不是一时兴起**：`search_messages` 要 `State<'_, Arc<Hub>>` 才跑得动（得拿会话表与对端表），
      单测里造不出 `Hub`；所以把能凭空构造的那一半抽成纯函数 `search_rows(msgs, query, k, named, peers)`。
      命令层只剩「取历史 + 取两张名字表」，**大小写与空词闸门只留在 `search_rows` 里那一份**
      （已经钉进静态合约：命令层再特判一遍就是两个地方会改一个漏一个 —— 写的时候它确实先在命令层做了一次，
      结果当场测出来「搜 FRIDAY」命中 0 条）。
    - **匹配面是「正文 + 文件名 + 引用摘录」三行拼的一整个串**：所以引用里那句话、图片的文件名都能搜到；
      读的是 `read_messages(usize::MAX)`，这一出口已挡 hidden，所以撤回与删过的天然不露。
    - **封顶两处**：结果 `SEARCH_LIMIT = 200`（按 ts 降序截，列满了补一句「先列最近这 200 条」），
      摘录窗口 `SEARCH_WINDOW = 24`。重读一份 JSONL 的代价与现状「拉齐 60 页再筛」同量级，几百条历史毫秒级。
    - **抽出来才发现的一处越界**：`search_snippet()` 在「定位不到命中」那一支（一道防御，正常走 `contains` 进来碰不到）
      直接拿 `SEARCH_WINDOW * 2` 当截取长度，没 `.min(cs.len())` —— 匹配面拼出来的那串比这个窗口还短
      （一条只有两三个字的消息）时，下面的 `cs[s..e]` 切片越界 **直接 panic**。单测拿一句「查不到」的短句
      把它抽了出来（期望的是「从头截一段、不添省略号也不 panic」），两头取窗现在都钳在原串长度内（也已钉进静态合约）。
    - **点一条就到位**：`openSession(sid)` → 逐页 `loadOlder` 直到那条出现（封顶 60 页与会话内拉齐同口径）
      → 滚到中间闪一下；输入有 250ms 防抖，**重画前用户又改了词就丢掉这份过时的**（否则两份结果互相盖）。
    证据：`cargo test --lib` 87 → 91（`全局搜索命中正文文件名与引用摘录`、`搜索结果行的会话名与会话栏同源`、
    `搜索摘录在命中处前后各留一窗`（字符数精确到 `1 + 24 + 2 + 24 + 1`，按字符切才能把整只企鹅带进窗口）、
    `历史再长搜索也封顶两百条`：250 条历史只回 200，且 ts 降序）；
    `session_route_check` 那一组判据（⌘F 弹层、 chips 切档重新发一次、点一条 openSession + 逐页拉齐 + 定位）；
    `prefs_layout_check` 新增两条静态合约（`query.trim().to_lowercase()` 全文件只出现一次且就在 `search_rows` 里；
    取窗两头都钳长度）。四个变异各只翻对应那一条：命令层加回一份折小写特判、摘掉 `search_rows` 的空词闸门
    （这两个同时让对应 Rust 单测红）、两头分别去掉一个 `.min(cs.len())`。

57. **存储：那几个数字与收件目录清理**（2026-10-27 加）。设置抽屉多一节「存储」，四行数字 + 「打开收件目录」
    + 三档清理（3 / 6 / 12 个月前）。
    - **一律走 `fs::symlink_metadata`（逻辑大小）**：递归统计里只要有一处用了 `metadata()`，iCloud「优化存储」的
      占位文件就会被顺手唤下来一次 —— 那不是统计，那是下载。单测
      `统计算的是逻辑大小不跟着软链去把文件唤下来` 拿一个指向 4KB 文件的软链验这一条：
      `inbox_bytes` 必须 `< 4096`（跟着链接算会把同一坨计两遍），`inbox_count == 1`（软链自己也是一个条目，个数要算上它）。
    - **清理只删「改得够老、而且没被任何还看得见的消息引用」的收件文件**，与「撤回不删文件」同一口径；
      只被 hidden 记录引着的那些可以清（本机已经不显示它了）。逐目录判 `dir_has_kept()` 再删，
      所以一个日期子目录里只要有一个文件被引着就整层留住。
    - **`storage_stats` 不进任何轮询**：它在 Rust 侧是递归走一遍目录树，只发生在抽屉打开、点「刷新」、
      以及清理之后（静态合约钉住了这一点）。清理返完顺手 `emit("storage-changed", …)`，数字跟着重画。
      （#58 把抽屉拆成两页后，这里的「抽屉打开」改成了「切到设置那一页」，三个时机个数没变。）
    - **`messages_count` 只算可见的那些**（走 `read_messages`）—— 把 hidden 的也算进去会给出一个「清完空了体积却没降」的
      难查状态；而 `messages_bytes` 算的仍是文件体积（行还在那儿）。
    - **清理没有目录时回 `(0, 0)` 且不把目录建出来**（统计与 `inbox_dir` 那边才顺手建，那里用户可能接着点「打开收件目录」）。
    证据：`cargo test --lib` 91 → 95（`存储统计算得出收件粘贴暂存与聊天历史`、逻辑大小那一条、
    `收件清理不动被聊天记录引着的那一层`、`收件清理只删够老的且不碰粘贴暂存也没目录时回零` —— 日期目录与 mtime
    靠 `File::set_modified` 造，不依赖时钟）；`session_route_check` 那一组判据（四行数字只在一进一退里各拉一次、
    「清理」两步确认且第二下只调一次 `inbox_cleanup`、`beforeTs` 就是当前那档换的天数）。三个变异各只翻对应那一条：
    去掉 `dir_has_kept()` 那道保留（被引着的那层也删）、时间闸门从「够老才删」改成反着判、
    `messages_count` 改成算全量（把 hidden 的也算进去）。

58. **配对设置抽屉拆成两页：配对是配对，设置是设置**（2026-10-27 改）。入口一枚没动（还是顶栏那枚
    「配对设置」），但抽屉里分成两页，标题跟着当前页走。以前口令、收件目录、心跳节拍、解绑全挤在一屏，
    只想改「响一声」的人得越过四五个不相关的框。
    - **归属只有一处取舍**：心跳「间隔」是 `prefs.json` 里的本机偏好 → 设置页；而「重新探测在线」与
      「解绑当前对端」是对端动作 → 配对页。其余按「改的是身份还是本机行为」分得很干净。
    - **切页只翻 `hidden`，不重建 DOM**：重建会把刚填一半的口令与「清理 / 删除」那两步确认的臂一起弄没。
      纵向节奏（`flex-direction: column` + `gap: 10px`）从 `.drawer-body` 那层搬到了 `.set-page` 上，
      多包一层不能把间距弄没 —— 这条也钉了静态合约。
    - **默认落「配对」那一页，收起再打开回到人刚待过的那一页**：当前页只存模块变量，不写 `prefs.json`，
      也不跨重启（与侧栏那两个源同一个口径）。
    - 顺手拆掉一个浪费：以前抽屉一打开就 `storage_stats`（递归走一遍目录树），而十有八九是来改口令的。
      现在只在「设置」那一页真露出来时读，同一次打开里来回切页还不重读。
    证据：`session_route_check` 354 → 359（默认落在配对页、只停配对页时不新增任何读取、切到设置页才把
    磁盘那两项填进界面、标题跟着页走、来回切页不重读、收起时页不丢；原有那条「收起再打开会重读」改成先确保
    停在设置页）；`prefs_layout_check` 284 → 293（九条静态合约：假 DOM 不解析 HTML，谁在哪一页、默认露哪页
    这类拆分布局只能静态钉）。八个变异各只翻对应那几条：去掉设置页开标签的 `hidden`（默认露错页）、
    把心跳下拉漏挪进配对页（归属那条与「id 全局唯一」那条一起红）、抽屉 toggle 里加回一句 `refreshStorage()`

59. **主窗置顶：对比工具栏那枚「置顶」**（2026-10-27 加）。用户原话是「mac 电脑上或者是 win 电脑上加一个按键一直显示在最前面」。
    先按「悬浮球」（独立小窗）设计了一版并问了四个决定，回答是「**不要这个，是在对比那个菜单添加一个按键就可以**」
    —— 需求是**主窗自己置顶**，不是第二个窗口。记在这里是为了下次别再往悬浮球那路上跑。
    - **走 Rust 命令而不让前端直调窗 API**，是查了权限表定的：`core:window:default` 那 28 条**全是只读 getter**
      （实测 `gen/schemas/acl-manifests.json`），`allow-set-always-on-top` 不在里面；而 `set_always_on_top`
      这个动作本身没有业务，单独一个命令既不加 ACL 权限，node 桩里也才断得到（前端直调那一路在假 DOM 里根本走不到）。
      命令里先 `get_webview_window("main")` 再 `set_always_on_top(on)`，**把落地后的值回给前端**。
    - **高亮只认命令回来的值，不做乐观翻转**：Rust 那边拿不到窗时，按钮绝不能亮着 ——
      「亮着而窗没置顶」是这一枚按钮唯一能骗人的方式，也是最难查的那种不一致。`tools/prefs_layout_check.mjs`
      里那个 `stubPinThrows` 一置就能把这条验红（变异 M1：先翻再调，五条行为同时红）。
    - **不存盘是用户选的**，理由：置顶是挡人的状态，「上次忘了关」如果跨重启还留着，比当场发现更难查
      （没人会去设置里找一枚按钮亮没亮）。但存了盘就必须有启动应用点，这一条做成了**条件式合约**：
      `Preferences` 里一旦出现 `pin` / `topmost` / `always_on_top` 这类字段，Rust 侧就得有≥ 2 处 `.set_always_on_top(`
      （命令层 + 启动读盘）—— 拦得住「只写盘不改窗」那半步。同理还有一条：前端若改成直调 `setAlwaysOnTop(`，
      capabilities 就必须含那条权限，**两边要么都无要么都有**（单判「现在没直调」会把后来改直调那一步默放）。
    - 顺手发现的一处技术债（**本次没动**）：`capabilities/default.json` 里现有三条
      `allow-set-fullscreen` / `allow-is-fullscreen` / `allow-toggle-maximize`，`js/` 目录一次都没用过
      （grep `fullscreen|maximize` 零命中）—— 死权限。
    - **平台边界**（已写进按钮 tooltip）：macOS 上别的 App 进全屏（独立 Space）后置顶窗不跟过去，
      要跨 Space 得设 `NSWindowCollectionBehaviorCanJoinAllSpaces`（`objc2` 依赖已在，未做）；
      Windows 的 `WS_EX_TOPMOST` 是同级互压，压不住全屏游戏和同样开了置顶的窗。
    证据：`prefs_layout_check` 293 → 306（行为八条 + 静态五条）；`cargo test --lib` 95 绿；其余四个
    node 检查全绿（本文件没改过的 session_route 仍 359）。七个变异逐个跑过：乐观翻转（M1，五条行为）、
    删掉 `generate_handler` 里那行注册（M2，只红静态那一条）、改成前端直调却不加权限（M3，六条）、
    高亮改用 `is-on`（M4，三条）、点击时顺手 `savePrefs({ pin })`（M5，只红「不写盘」那条）、
    HTML 里出厂就带 `is-active`（M6，静态那条 —— 假 DOM 不解析 HTML，行为层「出厂不亮」拿不到这个变异）、
    `Preferences` 加 `pub pin: bool` 但启动不应用（M7，只红条件式那条）。
    - **两处没实测**（假 DOM 与单测都碰不到窗）：① 置顶开着时弹原生选文件框（「打开对比」/选收件目录/
      另存为都走 `tauri-plugin-dialog`）会不会被自家窗压住 —— Windows 上 topmost 压住非 topmost 模态框
      是真实可能，真压住了就得「弹框前临时取消置顶、关掉恢复」；② 真机上置顶后逐个 Space / 多显示器看一眼。

## 八、对比视图：浏览侧栏（两个源 + 前后两张同时在屏上）

**列表有两个源可切，默认是「最近看过」。** 侧栏头部那两枚 tab（`#btn-src-history` / `#btn-src-dir`）就是源开关：

- **「最近看过」**（默认）：`history.json` 里那串看过的绝对路径（新载入 / 逐张翻看 / 放大看过都算），同一张只留一条、重复查看只置顶，最多 `HISTORY_MAX = 100` 条。
  行上第二格写的不是体积而是**相对时间**（`seenText()`：刚刚 / N 分钟前 / N 小时前 / N 天前 / 月-日）。
- **「当前文件夹」**：当前这张图所在的目录 —— 改动前唯一的源，那一套行为**一字没变**（自检里那批目录语义的判据共 19 条，全部改成「目录源下…」的措辞原样跑着）。

关键是**侧栏那套机器与数据源无关**：`buildStrip()` / `markStrip()` / 行拖拽 / 小图观察名单 /
`browseTo()` / `stepBrowse()` / `moveSel()` / `nextBrowseSlot()` **全部只读 `browse.items` 与 `browse.idx`**，
换源就是换喂给 `items` 的东西（`applyHistory()` 与 `ensureFolderList()` 两条喂法），不是另写一套侧栏。
所以下面那些**落窗轮转、拖行、键盘**的规则两个源完全共用，不必重看一遍。

**记一次查看分两层：发命令的口子只有一处，接线有三处。** 低层是 `api.js` 的 `noteViewSeen(path)` ——
`invoke("record_view")` 全项目只在那一句里（三个视图各写一份就会有三套去重/截断口径，同一张会被记成两条），
失败也只在那一处 `setStatus("记录查看失败: …")`，绝不静默吞。往上是三条接线：

1. **新载入**：任何途径（⌘O、单击空窗、拖文件进窗、⌘V 粘、系统「打开方式」、收藏与传输里的「在对比中打开」）
   载入一张**带本机路径**的图，都汇到 `fillPanes()` 末尾的 `noteLoaded()` → `recordView(path)`。**不 await**
   （一次图片载入不该卡在磁盘写上）；返回值就是整份新列表，直接拿来渲染，**不再多发一次 `get_history`**。
   冷启动那一次例外（`loadHistory()` 拉一次填默认源）。
2. **侧栏逐张浏览**：`browseTo()` 走的是 `assign()` 而不是 `fillPanes()`，**根本不经过第 1 条那条路** ——
   在目录源里把整个文件夹翻一遍，就是靠这一步才一张不漏地进历史。它传 `reorder: false`：照样写盘，
   但这一趟不拿返回值重排侧栏（否则历史源下每按一次方向键就把当前行顶到第一行，列表会一边翻一边跳、
   下一张也跟着变），只把最新那份存进 `browse.history`，切走再切回历史源时看到的就是最新顺序。
3. **放大看过**：传输 / 聊天视图点缩略图开 `openLightbox()` 也记一条 —— 放大就是真看过。
   那儿只调低层写盘、不碰侧栏渲染（侧栏在另一个视图里，压根看不见）。

`noteLoaded()` 还做第二件事：按 `browse.source` 分流 —— `"dir"` 才走 `ensureFolderList()`；`"history"` 什么都不用做。

所以：

- **「收到」不等于「看过」**：传输落盘但既没在对比视图里显示过、也没点开放大过的文件不记；载入失败的也不记（三条接线都在真看到之后才走）。
  粘贴进来的图会记，于是 `pastebox/` 里那串 `剪贴板图片-<时间>.png` 会占掉列表的位置 —— 这是已知代价，100 条上限本身就是保护，不做特殊过滤。
- 只有名字没有路径的来源（浏览器兜底、`input[type=file]` 递出的 0 字节 File）没得记，也列不出东西；
  目录源下侧栏保持收起，并在提示位原文写「这个来源没有本机路径，列不出文件夹」，不假装「目录里没有图」。
- 同一个目录不重发 IPC，只把当前项对齐；换了目录才重新列一次，并清掉上一目录的小图与失败记录。
  **切源与历史渲染都不清 `thumbCache`**（见第七节第 40 条），**也不自动删失效记录**（见第 39 条）。
- Rust 只回原始条目（不排序），**自然序在前端做**：`localeCompare(name, "zh-Hans-CN", { numeric: true, sensitivity: "base" })`，
  天然得到 `IMG_2 < IMG_10 < IMG_100`，不需要在 Rust 里手写数字比较。历史源**不排序** —— 它的顺序就是 `seen` 降序，后端已经排好了。
- 递归子目录、循环浏览、把 ⌘O 多选那几张当队列、传输/收藏视图里的浏览入口 —— 本轮都不做；
  历史也**不做单条删除、不做搜索过滤、不做跨设备同步、不做真缩略图**（沿用「只解可见行」那套观察名单，100 条也不会一次读 100 张盘）。
- **源选择不进 `prefs.json`**：每次启动都是历史源。跟侧栏开合、分隔条比例同一个口径 ——「那是单次会话自己的事」（第九节）。

**落窗按可见窗序列轮转**：`browse.slot` 记的是**上一次落在哪个窗**，下一次浏览就去「当前档可见窗序列
（`LAYOUT_KEYS[layout]`，顺序 a→b→c→d）里它的下一个」，到末尾绕回第一个 —— 两图下就是原来的严格交替
（A↔B，行为一字不差），四图下 A→B→C→D→A、**屏幕上始终是连着的四张**（不是只动 A/B、把 C/D 空着），
所以第一次浏览也绝不会把刚手动打开的那张顶掉；`btn-clear` 清空后把 slot 记在**序列最后一个**，
下一次浏览绕回 A（列表保留，因为目录还是那个；两图下就等价于原来那句「slot 写 b」）。
**单图布局下这条规则退化** —— 序列只剩 A，没得下一个可去，`nextBrowseSlot()` 直接回 `"a"`，
点一行 / 按 `[`/`]` 就是换掉那一张（状态条也只写「第 N/M 张」，不再提别的窗）；
四图下状态行会列出其余三格：「第 N/M 张→B 窗，A/C/D 窗留着前面几张」。
读失败（文件被移走/改名）时**既不动 slot 也不推进游标**，只把那一行标灰 —— 对照位不能被一次失败的浏览悄悄换掉。

**想指定落哪一格就把那一行拖过去**：按住侧栏任意一行往图窗上拖，移动超过 4px 才算拖，不够就还是一次
普通点行（两套互不打扰，同一个 `mousedown` 分出来）。拖时跟手那枚牌（`#strip-ghost`）写文件名，
图取不到就不挂（能转出 asset 地址就直接指文件，否则用 LRU 里那份，两样都没有就只留名字），
**绝不为拖一下现读盘**；落点窗复用 `.drag-over` 描边 —— 与从 Finder 拖文件进来同一个样子。
**放到哪格就是哪格**，那一格原有的图直接替掉、不弹确认；落点只在**当前档的可见窗**里找（`paneAtPoint()` 走
`visiblePanes()`，两图下拖到 C/D 的地盘等于没拖，与上面那条轮转同一口径）。拖完 `browse.slot` 就记成那个落点窗（汇流到
`fillPanes()` 那唯一一处接线），下一次浏览自然走它的下一格 —— 拖与点不是两套规则，是同一条。
半途按 `Esc` 整趟作废（松手在哪都不载入，也不让同一个 Esc 再去收侧栏）；拖完紧跟的那一下 `click` 会被吐掉
（`stripDrag.swallow`）：松手落在侧栏里时浏览器照样会在同一行上补一个 click，那一下会把已经作废的一页又翻出来；
下一次按下就复位，不会连着吃两次。
**为什么不用 HTML5 的 `draggable`/`dataTransfer`**：`dragDropEnabled: true` 下 macOS 那条通道只认从 Finder
递进来的文件路径，页面内的 draggable 会被原生拦截吃掉（对比视图里 `vp.addEventListener("drop")` 就是因此只在浏览器下跑），
所以这全程自己拿鼠标算：`mousedown` 记起点 → window `mousemove` 判阈值与跟手 → `mouseup` 收尾，另加一道
`ev.buttons === 0` 兜底（专治拖出窗口外 mouseup 根本不来的情况，否则牌与整页禁选会卡在屏幕上）。

**键盘选中即显示**（`↑`/`↓`/`Home`/`End`）：这三个键与点行汇到同一个 `browseTo()`，
所以“在左侧选到哪一行”与“右边正在看哪一张”永远是同一件事，不存在“选中了但没显示”这种中间态。
行上因此也**只留一层视觉状态**：`.fs-row.is-current` 的底色 + 左侧那根竖条。原先 `.is-sel` 还会另描一圈
`inset` 框，↑↓ 改成选中即显示后两者永远落在同一行，那圈框纯属重复描边，已按用户要求拆掉
（类名仍挂在 DOM 上，自检的 `selIndex()` 与 devtools 靠它读“选中在哪一行”）。
侧栏本体（`<aside tabindex="0">`）也不再画焦点框：原先是 `.filmstrip:focus-visible { outline: 1px solid }`，
现已换成写在 `.filmstrip` 上的 `outline: none` —— **只删那条规则是不够的**，点行与 Tab 进来都会走
`focusStrip()` 的程序化 `focus()`，拆了自定义样式只会让 UA 默认焦点环冒出来，症状看着一模一样。
这三个键另外还会走两道**短路**（都在 `browseTo` 开头）：
- **已经在看这一行**（顶到首尾再按、`Enter`/`Space` 确认都会走到）：`index === browse.idx` 且这一张**确实还画在某个可见窗里**
  （比对 `p.meta.path`，不能只看游标 —— 中途 ⌘O 手动换过图时游标还是旧的，落在隐藏窗里也算没在看）才直接返回。
  不短路的话，两图下会把同一张再往对面窗塞一次（看着像“莫名多出图”），还白读一回盘。
- **连按方向键**：上一张还在读时 `browse.inflight` 占着，新按的那一行记到 `browse.wanted`（只留最后一个），
  这趟读完再追一次 —— 合并的是**显示**（中间那几张不停下来看），不是丢请求（每张该读的都读了）。
  那一次没读成也要把 `wanted` 作废，否则下一次浏览会莫名跳到陈旧的一行。

**「对齐」靠的是已有的同步模式**，浏览这一层没有新发明：`Pane.setImage()` 里新载入的窗会沿用参照窗的
`scale/x/y`，所以前后两张自动停在同一区域，翻着翻着不会越看越歪。

### 侧栏小图怎么来的：屏上看得见几行就挂几行

**只要 `convertFileSrc()` 拿得到地址，行上的小图就是直接指本地文件**（`api.js` 的 `assetSrc()`）：缩放与解码全部
交给 WebView，不过 JS 的手，一个字节也不往 IPC 上搬；`read_image` 解不了的 svg/avif 也能显示了。地址形如
`asset://localhost/<百分号转义后的路径>`（Windows/Android 上是 `http://asset.localhost/...`），所以路径里的中文与空格
全靠转义，那一条在 `folder_browse_check` 里有专门用例。

代价是要**三处同时到位**（漏一处就是缩略图整片空白，而且只在真机上出现，第七节 #31 说的就是这件事）：

| 位置 | 管什么 |
|---|---|
| `js/api.js` 的 `assetSrc(path)` | 从 `__TAURI__.core` 与 `__TAURI_INTERNALS__` 两个注入点取 `convertFileSrc`；函数不存在、路径为空、抛错这三种情况**统一回 null**（绝不抛，抛了侧栏就卡死），null 就是「该走退路」的信号 |
| `tauri.conf.json` 的 `app.security.assetProtocol` | `enable: true` 开协议；`scope` 给可读范围。只开协议不给范围，WebView 照样取不到文件。**scope 用的是 `glob::Pattern`：`**` 必须独占一个 `/` 段，且 mac/Linux 上 `\` 不是分隔符** —— 写 `C:\Users\**` 的话 schema 与 `cargo build` 都过得去，启动时直接 panic（见第七节 #32）。盘符也不枚举，靠一条 `**` 兜住所有盘 |
| `tauri.conf.json` 的 `app.security.csp` | `img-src` 里得收 `asset:` 与 `http://asset.localhost`。漏了这条，请求被 CSP 直接拦，图位上一个错也不报 |

`scope` 是 JSON，写不了注释，口径就一句：全盘通配 —— `/**` 加一条 `**`（后者兜住带盘符的路径），
再加上 `$HOME/**`、`/Volumes/**` 这几条把「用户目录与外接盘也能读」写明白。
因为这个工具本来就是「看本机任意目录里的图」，侧栏能列出来的东西不能取不到图。
要收紧就改 `scope`，但记得同步收紧 `read_folder`/`read_image` 那侧，不然两边口径不一样更难查。

**为什么是一条 `**`，而不是枚举盘符**：拿同一个 `glob` crate（0.3.4）在 mac 上实测过 ——
`/**` 匹配不到 `C:\Users\foo\a.png`（分隔符不对，整串算一个段），而 `**` 匹配任意多个段，
所以 `C:\...`、`F:\...`、网络盘、乃至 `is_allowed()` canonicalize 后的 `\\?\C:\...` 都在范围内。
枚举 `C:`/`D:`/`E:` 是个永远在补漏的写法（F 盘下一个就撞），所以不写；这条也用合约钉住了
（scope 必须含 `**`，且不得出现 `^[A-Za-z]:` 开头的枚举）。
不过要说清：`**` 命中 Windows 那些路径只是按「匹配任意多段」推出来的，**本机无法跑真 Windows 验证**，
所以下面那道 `onerror` 兜底是必需品而不是可选项。

**屏上看得见几行就挂几行**（2026-10-26 定稿，第七节 #45 有这次的经过）：`IntersectionObserver` 负责
「滚进来就挂、滚出去就摘位图」；另外 `visibleRowRange()` 用 `getBoundingClientRect` 纯几何算一遍可见行、
`scroll` 上挂了 80ms 节流的 `requestNearThumbs()` 补挂 —— IO 漏发或被节流时也不至于让某一屏一直空着。
容器收着（侧栏隐藏）时所有 rect 都是 0，所以那函数先看 `box.bottom > box.top`，不然「全都可见」会一次把
整目录读一遍。

**拿得到地址不等于取得到文件**：scope 没覆盖、文件刚被取走、上面那个 Windows 路径问题，`convertFileSrc()` 都是
正常返地址、只是那张图 `onerror`。所以 asset 图一律挂 `onerror`：抹掉破图、改走 `read_image`，并把这个**路径**
记进 `assetBad`（`Set`）—— 此后只有这一行不再试 asset，同目录其它行照旧直挂；同一路径只认一次，不会每滚
一回视口就多一次失败请求 + 一行日志（原来是 `assetDead`，一张坏图就让整列掉进慢路，几百张目录会变成
几百次 IPC）。

**退路也照样「可见即挂」**：纯浏览器里调试（没有 `convertFileSrc`）或转地址失败时，用 `read_image` 拿整图
base64（上限 80MB）。常数集中在 `view-compare.js` 的 `STRIP_*`，要调就改那一块：

| 闸门 | 值 | 意思（**仅退路**） |
|---|---|---|
| `STRIP_DECODE_WINDOW` | 1 | 只给「连 `IntersectionObserver` 都没有」的环境兜底：那时只解当前项 ±1 |
| `STRIP_AUTO_MAX` | 4MB | 与传输视图 `PREVIEW_AUTO_MAX` 同口径：过大的不自动解，行上给一个「大」字占位，要让这一行显示出来（点行 / ↑↓ 选中 / `[`/`]`）才走一次 IPC |
| `STRIP_LRU_MAX` | 40 | 内存里最多留 40 张整图 data URL：一屏 13~17 行要装得下（8 张那个旧值会让滚回来的行重新读盘）。**淘汰只清缓存、不摘屏上的图** |
| `STRIP_INFLIGHT_MAX` | 3 | 同时发出去的 `read_image` 封顶；超出的进 `thumbQueue`、在 `finally` 里接上 —— 直接丢会让一屏里靠后的那几行永远空着 |

两个顺手省盘的细节（都只在退路里有意义）：`browseTo()` 载入大图成功后会把那份 data URL **塞进 LRU**，
所以点一行只读一次盘，不会大图小图各读一遍；换目录时 `buildStrip()` 先 `stripIO.disconnect()` 再重建行，
并把 `thumbQueue` 清空（旧索引没有意义），否则换过几个目录后观察名单会把已被拆掉的旧节点一直强引用着。

Rust 侧始终出不了真缩略图（刻意不带 `image` 依赖，`Cargo.toml` 里连 arboard 都关了默认特性）；
真要服务端生成的 128px 缩略图 + 磁盘缓存，得先把这条依赖口径改掉，那是另一个决定。

### 行上的名字：从中间裁，不是从末尾裁

侧栏那一列只给 `STRIP_NAME_MAX = 16` 个字符，超出由 `shortName()` 从**中间**裁：
`Generate_Amazon_background_image_2K_20261025150443.jpg` → `Genera…50443.jpg`。
为什么不用纯 CSS 的 `text-overflow: ellipsis`（它一直在 `.fs-name` 上，但只在名字比列宽还宽时才兜底）：
这类图（UUID、微信哈希、带时间戳的生成图）开头一个样、区分点全在尾部，从末尾裁会把时间戳和扩展名
一起吃掉，两条微信图会被裁成一模一样。裁的只是显示文本，`row.title`（整条路径）与 `dataset.path` 都是完整的，
悬停能看全；`tools/folder_browse_check.mjs` 第 13 节拿用户实拍那几条名字核了具体的裁法。

16 这个数是按列实宽定的，不是拍脑袋：侧栏 190px 扣掉 padding、序号、小图与两个 gap 后只剩 ~102px，
`.fs-name` 因此降到 12px（body 继承下来是 13px）让 16 字符刚好放进去。前提是先给 `.filmstrip` 补上
`min-width: 0` —— 没这句时侧栏会被 nowrap 的长名字撑到几百 px，定宽与裁切全部白做（#23）。

几个样本的裁法：`image.png_2K_20261025174057.jpg` → `image.…74057.jpg`、
`WeChat4dfa9b61996222cdb06be62a8a5b85d09.jpg` → `WeChat…85d09.jpg`、
`f6fd84b2-b8c0-418e-ab62-441064623d64.jpeg` → `f6fd8…23d64.jpeg`；16 字符以内的（`IMG_2.png`）一字不动。

### 结构上唯一一处不能改的地方

侧栏是 `<main class="stage">` 的**兄弟**而不是子元素，两者一起包在新加的 `.cmp-body` 里。
原因：分隔条按 `ui.stage.getBoundingClientRect().width` 算百分比并写 `flex: 0 0 x%`，
侧栏挤进 stage 会让两窗总宽溢出、拖拽比例全错。包一层则分隔条逻辑一行都不动。
收起只靠 `hidden`（style.css 里那条 `[hidden] { display: none !important }` 统一规则），别再写高优先级的 display。

### 已知边界

- 目录源下目录里只有当前这一张：列表照常显示（就一行），`[`/`]` 只会说「已经是第一张/最后一张（共 1 张）」，不循环。
- 目录源后端封顶 `FOLDER_MAX_ITEMS = 2000`，`truncated` 字段跟着回，前端在列表底部写「目录过大，只列出前 2000 张」；
  历史源封顶 `HISTORY_MAX = 100`，**没有提示也不能回滚** —— 第 101 张进来时最旧那一条直接掉出去（那个上限是防膨胀与防「翻不到头」，不是性能阈值：侧栏一次全渲染行本身很轻，小图只解可见那十几张）。
- 「列表」按钮只在**两个源都空**时才禁用（只看当前源的话，历史被清空就按不亮、也堵掉切回目录源那条路）。
- 侧栏头部那两枚 tab 挤的是 190px（#23）：字号 11px + 内边距 1px 5px 刚好放下「最近看过 / 当前文件夹」两个短词，再宽一点就撑破那一行。
- **iCloud「优化存储」的文件**：`std::fs::read` 会触发按需下载，症状是点侧栏某一张长时间停在「读取中」
  （退路里小图那趟 `read_image` 失败还会把那一行标灰；asset 模式下取本地文件同样会触发下载，症状是那一格迟迟不出图）。
  这不是链路坏了，先在 Finder 里把那张图下载到本地。历史源下同一张只会表现为「那一行是灰的」，**不会因此被删掉**（#39）。
- 「清空查看历史」只清 `history.json`，**不动任何图片文件本身**；`pastebox/` 里那些粘贴生成的文件也不动（那里「只增不删」的口径没改）。
- `Esc` 只在**焦点在侧栏上时**收侧栏；放大层打开时 Esc 仍先关放大层，这个优先级没动。对比视图里还多一层：**设置抽屉开着时 Esc 先收抽屉**，才轮到侧栏。
- 用户自己收过一回侧栏（`⌘⇧B` 或行尾那个「×」）就不再自动弹出来抢地方，直到他再按一次开关。**切源不算用户开关侧栏**（`setStripSource()` 全程不碰 `browse.open`）。

## 九、系统设置与三档布局

对比视图的设置只有**三项**：显示几张图、是否同步、滚轮/触控板双指干什么。
前两项是**一处设置两个入口**（工具栏 + 抽屉），滚轮行为**只剩抽屉一个入口**（工具栏那枚已按用户要求撤掉）；状态一直只有一份。
（`prefs.json` 里还多出来三项 `notify` / `inbox` / `inbox_layout`，那是传输视图「本机接收」的，见本节末与第四节。）

| 项 | 工具栏 | 「设置」抽屉（`#cmp-settings`） | 快捷键 |
|---|---|---|---|
| 显示图片数量 | 只有 `1 图` / `2 图` 两枚分段按钮（**四图 2×2 不在工具栏上**） | 下拉「显示图片数量」（三档都在） | `3` / `2` / `4` |
| 图片同步 | 「同步」开关（`#chk-sync`） | 开关「图片同步」（`#chk-set-sync`） | — |
| 滚轮行为 | **工具栏上没有这一枚**（`#sel-wheel` 已拆） | 下拉「滚轮 / 触控板双指」（`#sel-set-wheel`，**唯一入口，也是真值所在**） | — |

另有一枚**窗口置顶**（`#btn-topmost`，工具栏最右）：它是窗口的**运行态**、一个字不写 `prefs.json`，
所以没算进上面那三项里（用户选的就是「每次启动都从普通窗开始」）。详见 #59。

任一处改动都**只传改动那一项**写盘（`set_prefs` 里未传的字段保持磁盘原值）。
滚轮的真值现在存在抽屉那枚下拉上，读它的只有一处 —— `wheelMode()`（`view-compare.js`，与 `isSync()` 同一个写法），
`currentPrefs()` 与滚轮监听都走它。拆工具栏那枚时只删 HTML 是不够的：`ui` 里的 `wheelSel` 引用、
两个入口的互相回写、以及滚轮监听里那句 `ui.wheelSel.value === "pan"` 都得改成读 `wheelMode()`，
否则滚轮会默默固定在默认那一档。
抽屉本身不是设置、只是一个覆盖层：工具栏 `#btn-cmp-settings` 负责开合与高亮，Esc 或抽屉里的「收起」（`#btn-set-close`）关掉 ——
**高亮与开合走同一个入口 `setSettingsOpen()`**，否则抽屉收起来了、工具栏那枚还会长亮着。

### 三档布局分别是什么

| 档 | 可见窗 | 落窗规则 | 备注 |
|---|---|---|---|
| `1` 单图浏览 | A | 点列表行 / `[`/`]` **就换掉那一张** | 只剩一个窗，「同步」两个入口一起禁用（灰掉 + `pointer-events: none`），状态不丢，切回多窗又生效 |
| `2` 两图并排（默认） | A / B | 严格交替（第八节） | 唯一能拖分隔条的一档 |
| `4` 四图 2×2 | A / B / C / D | 按 A→B→C→D→A 轮转，四张同时在屏上（第八节） | stage 是 grid，分隔条收起 |

表里那列「落窗规则」说的只是**自动**那一条（点行 / `[`/`]`）：三档下都还可以**把侧栏那一行直接拖到指定的那格**，
当前档的可见窗都接受（单图下只有 A，两图下只有 A/B），非空窗也直接换掉 —— 见第八节。

布局不只是一个布尔开关：以前是「网格 / 不是网格」两态（`grid-mode`），现在是三态，
JS 里 `LAYOUT_KEYS` 与 CSS 里 `body.layout-1/2/4` 共同承担可见性（同改约束见第七节第 17 条）。
「浏览一张图片」做成**一档布局**而不是一个临时模式（已确认）：它跟 2/4 图是同一个轴上的三档，
而不是另一套正交开关，否则要多面对「单图模式下选了 4 图」这种组合。

### 存了什么、什么时候写

- `prefs.json` 五个字段：`layout` / `sync` / `wheel` / `notify` / `inbox`（Rust 侧 `Preferences`，`store.rs`）。读写它的命令：`get_prefs` / `set_prefs`（`prefs.rs`），外加两条新给本机接收用的 `inbox_dir` / `play_notify_sound`（`net/mod.rs`，前者回「当前生效路径 + 改过没有」、后者无视开关直接响一声）。
- 出厂态：两图 + 同步开 + 滚轮缩放 + 响一声 + 默认收件目录，与 HTML 里写死的那一份一致（**两边不一致就会出问题：「读到空」与「读到默认」得表现出同一个行为**）；**首启动不会自动写一份文件**。
- 读只读一次：模块加载末尾的 `loadPrefs()`，异步 —— 所以首帧按出厂态排布，读到存的那一档再切过去。
  这就是 `body` 要带 `class="layout-2"` 而不是等 JS 加类的原因，不然 B 窗会先被藏一下再露出来。
- 非法值在进后端前就被前端拦下（`LAYOUTS.includes`），`set_prefs` 自己也会 `Err`；
  手改坏的 `prefs.json` 则由 `normalize()` 退回默认，不会把界面带进一个没有 CSS 的布局（那比退回默认难查得多）。
- 非 Tauri 环境（浏览器直开 `js/index.html` 调试）这几条命令都挂，一律当「存不上」处理：界面照常可用，只是下次启动回到出厂态。

### 本机接收的三项（同一份 prefs.json，入口在传输视图抽屉的「设置」那一页）

| 项 | 字段 | 入口 | 生效点 |
|---|---|---|---|
| 收到消息时响一声 | `notify`（出厂 `true`，走 `default_notify()`） | 「配对设置」抽屉 →「设置」那一页 → 本机接收 → 开关 + 「试听」 | `Hub::notify_arrived()` → `net/sound.rs::play()`，见 #34 |
| 收件目录 | `inbox`（空串 = `<数据目录>/inbox`） | 同一段：选择… / 恢复默认 /  打开目录 | `Store::inbox_dir()`，工位与启动建目录问它；摊平目标再问 `inbox_delivery_dir()`（见 #47）|
| 收件目录里怎么摆 | `inbox_layout`（`day` / `month` / `flat`，出厂 `day`） | 同一段：下面那个下拉 | `Store::inbox_delivery_dir()`，只影响摊平目标那一层 |

- 参数名除 `inboxLayout` 外都是**单词**（`notify` / `inbox`）：第七节第 1 条那个 camelCase 坑的续集 —— 写成 `inboxDir` 不会报错，只会永远不生效，所以这条已钉进静态合约。
- 摆放方向存的是白名单里的三个词（`day` / `month` / `flat`）：`set_prefs` 验不过就 `Err`，`normalize` 把空串与手改坏的值退回 `day` —— 两边不一致时，会出现「界面写着按月、文件全进了根」这种最难归因的状态。
- 收件目录只收**绝对路径**：`normalize()` 把相对路径静默清回默认（读取路径上没有报错出口），而 `set_prefs` 里 `check_inbox()` 是硬闸门（绝对路径 + `create_dir_all` + `is_dir`），验不过直接 `Err` 且不动磁盘旧值 —— 宁可不存，也不要存一个「点了没反应还不报错」的值。
- `Store::inbox_dir()` **不加缓存**：每次落盘多读一遍不到 1KB 的 `prefs.json`（一条消息三次），比同一次的 sha256 便宜几个数量级；加缓存就要动 `Store` 的无状态形态，换来的只是「改了目录得重启才生效」这种更难查的行为。
- 「打开目录」复用 `reveal_in_folder`，「选择…」复用 `pick_folder`（只多了一个可选的 `title` 参数，默认仍是「选择要发送的文件夹」）—— 不新增第二个文件夹选择器。

### 存储：那几个数字与收件目录清理（「设置」那一页的最后一节）

四行数字（收件目录 / 粘贴暂存 / 聊天历史 / 数据目录合计）+「刷新」+「打开收件目录」，加一个三档清理下拉（3 / 6 / 12 个月前）与「清理」那枚。这一节**不往 `prefs.json` 里存任何东西**：它是纯读的，唯一改变盘的动作就是「清理」。

| 行 | 后端那个键 | 怎么算 |
|---|---|---|
| 收件目录 | `inbox_bytes` / `inbox_count` | 递归走生效的收件目录（`Store::inbox_dir()`，改过也算那儿） |
| 粘贴暂存 | `pastebox_bytes` | 递归走 `pastebox/`（**只算不删**：那一批仍是「只增不删」，气泡 `path` 指的就是它们） |
| 聊天历史 | `messages_bytes` / `messages_count` | 文件体积是整份 JSONL（含已标 hidden 的行），条数只算**还看得见**的那些 |
| 数据目录合计 | `data_bytes` | 整个数据目录递归求和。**收件目录被人改到数据目录之外时它就不含那一块** —— 所以那三行加起来可能反而比它大，这不是算错 |

- **读的时机只有三个**：切到「设置」那一页、点「刷新」、清理之后（停在「配对」那一页时一个都不读）。`storage_stats` 在 Rust 侧是递归走一遍目录树，把它放进任何轮询里都划不来（已钉进静态合约）。
- **算的是逻辑大小**（一律 `fs::symlink_metadata`）：只要有一处用了 `metadata()`，iCloud「优化存储」的占位文件就会被统计顺手唤下来一次 —— 那不是算体积，那是下载。
- **命令整个没回也只把这一节写成「读取失败」**，不额外弹 toast：那一页刚露出来就被一句报错抢掉视线，比数字没刷出来更烦人。
- **清理只删收件目录里「改得够老，而且没被任何还看得见的消息引用」的文件与日期子目录**（口径与「撤回不删文件」一致）：粘贴暂存不动、聊天记录本身不动、被引着的那个日期子目录整层留住。一个月按 30 天算 —— 这是个粗清理的门槛，不是日历账。**删掉的个数按文件计**（整个日期子目录被清掉算 N 个，不是 1 个）。
- 「清理」沿用两步确认（第一下只把文案换成「再点一次确认清理」，4 秒退回）；**档位读在第二下这一刻**，不然臂上之后改了下拉还是按旧那档删。完成后 toast「删了 X 个文件，释放 Y MB：聊天里引着的一个都没动」，一个都没删成时那句要说清原因（都被聊天记录引着），不静悄悄。
- 数字格式复用 `fmtSize`（与其他视图同一个写法）；节点一行一行摊出来而不是拼一大段 `innerHTML`（将来要按行加「点开看目录」的入口，节点先留着）。

### 已知边界

- 「同步」只管缩放平移一致，**不影响哪张显示在哪个窗**；单图下它没有作用对象，所以是禁用而不是隐藏（用户得知道为什么不能点）。
- 侧栏的开合状态、列的是哪个源、分隔条拖出的窗格比例都**不进 `prefs.json`**（那是单次会话自己的事；切布局时还会把 inline flex 抹掉）。副作用要说清楚：每次启动都是默认的「最近看过」，上一回看的是某个目录这件事不会留到下一次。
- 窗不可见时不会把图塞到一个看不见的窗里：`fillPanes()` 会把这种落点降级成可见窗（「打开 A/B/C/D」 四个入口已拆，现在指定落窗只剩「单击那个空窗」，而空窗本来就是可见的，所以这条降级如今只是防御）。
- **工具栏上没有 `打开 A/B/C/D`，也没有「4 图」那枚按钮**（用户要求）：要往指定窗里放图就单击那个空窗（先试粘剪贴板、没图才弹选文件，落点就是点的那格）、拖文件进窗，或者 ⌘V；一次多张走「打开对比」（⌘O，自动铺满可见窗）。四图布局只能从设置抽屉里选（快捷键 `4` 仍可用），所以**四图下工具栏那两枚都不亮**，取态看抽屉里的下拉。
- 改过收件目录后，收到的文件就不在数据目录里了 —— 按第一节那份「拷九个东西」的备份流程**不含它们**（⚠️ 已写进第一节）；按天/按月分出来的日期子目录也在那里，备份时别只拷 `inbox/` 这一层。
- 图片右键菜单已盖了三处：对比视图（图窗 + 侧栏）、传输视图的聊天气泡（整条都拦，一份菜单管三种气泡）、以及放大层（`#lightbox-menu` 五项）。放大层那一份**没提到 `api.js` 里共用**是有意定的：命令实现本来就在 `api.js`，而三个视图的菜单 DOM 与显隐需求本来就各有一份（对比视图多「发送到聊天」、气泡菜单多撤回/删除/引用/转发、放大层那五项在有路径时全露），抽公共反而绕。唯一保留的系统菜单是**放大层里没有落盘路径时不拦**（粘进来的纯位图，那里只有「拷贝图像」有用）。
- **引用回复与转发在老对端上会降级**：它只看到你发的正文那一句（那张引用卡片不显示），不会报错也不会拒收 —— 新字段一律 `#[serde(default)]`，换回来的代价就是这一句显示上的差别。
- **清空聊天记录不腾空间**：它只是把这一台不再显示的那些行补上 `hidden`，`messages.jsonl` 一行没删（而且不删行是存心的：只追加、不重写）。真要腾空间就删收件目录里的文件（抽屉里那个「清理」就是干这个的），或者退出后手工清目录。
- **全局搜索只搜这台机器还看得见的消息**（撤回与删过的天然不露），封顶 200 条；与会话内那条小框是两套语义（那一边只筛已铺出来的），不共用数据也不互相抢。
- `tools/prefs_layout_check.mjs` 的假 DOM **不解析 HTML**，所以显隐那部分不是真渲染，
  而是对 `style.css` / `index.html` 源码做字符串核对的「合约」（那一节的第 9 部分）；真机目视仍然必要。
  听不见声音、碰不到真实文件系统也是同理：提示音与收件目录（含摆放）那二十几条合约只能钉住「改动都在」，
  「真响了吗」「文件真落进去了吗」只有真机能答 —— 这一块是真机 `net_selftest` 在核（它按 `prefs.json` 算落点）。
